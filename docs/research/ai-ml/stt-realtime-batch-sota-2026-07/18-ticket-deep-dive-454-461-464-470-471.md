## TASK-461 — SDK Reconnect UX + Transcript Wire Contract (C6-02 · C6-03 · C6-04 · C5-05)

**Status** (line 3, verbatim): `Review`

**Requirement Analysis** (`## Requirement Analysis`, lines 33–48): Four SDK/playground defects on the best-effort **realtime** loop (never the durable transcript) that leave the clinician-facing surface either lying about its state or quietly corrupting data. On a clinical surface, a stuck "reconnecting" spinner or a silently-dropped caption erodes trust and can prompt a needless mid-consultation restart. The two drop/disconnect-relevant findings:
- **C6-02**: `onReconnect` sets `status = 'reconnecting'` but nothing ever transitions back to `streaming` after a successful auto-reconnect — the clinician reads a permanent "reconnecting" on a healthy stream and may restart a working consultation.
- **C6-03**: on terminal reconnect failure, `onReconnectFailed` sets error+status but returns without cleanup — the microphone track stays live (recording indicator on, privacy surprise) and the gateway-side streaming session is never `DELETE`d (held concurrency slot).
(C6-04/C5-05 are transcript-payload-tolerance and NER-dedup fixes, not disconnect/drop-visibility per se, but noted for completeness since they're in the same ticket.)

**Implementation Summary mechanism** (`## Implementation Summary`, lines 89–120):
- **Reconnect-success signal** — the scaffold's premise was wrong (verified against code): `onReconnect` actually fires at attempt-**start**, not on success, and `onopen` fired no success callback on a reconnect. Fix added an **additive** callback: private `onReconnectedCb`, public registrar **`onReconnected(cb)`** on `SttV2WebSocketClient.ts`, fired from `onopen` guarded by `wasReconnecting` (never fires on the initial connect). `use-live-stt-session.ts` registers a handler that sets **`streaming`**, guarded by the same `statusRef` check the disconnect handler uses (so an in-flight `stopping`/`idle` is never clobbered).
- **Terminal-failure cleanup (C6-03)** — `onReconnectFailed` now mirrors the handshake-fail path: `wsClientRef.current = null` → **`releaseAudio()`** → **`void closeStreamSession(sessionIdRef.current)`** (null-guarded, no double-close) → null the session ref → `setSession(null)` → `setError(GENERIC_AUTH_COPY)` → `setStatus('error')`.
- **Wire-contract tolerance (C6-04)** — new shared type **`WsTranscriptWirePayload`** in `types/stt-v2.ts` (all-optional, dual-cased, `unknown`-typed, index signature); `normalizeTranscript` now degrades gracefully — only a payload with no string `text` is dropped; absent `startTime`/`endTime` default to `0`; new **`coerceIsFinal()`** helper accepts boolean, numeric `1`/`0`, or string `'1'`/`'0'`.
- **Follow-up fix (same ticket, discovered on review)**: `acknowledgeConnection()` (the reconnect-attempt counter reset) had no production caller, so the `maxAttempts` budget depleted cumulatively across a session instead of per-episode. Fixed by resetting on the **first server message after a reconnect**, wired into `handleMessage`, guarded by `isReconnecting` — preserves the existing `BUG-04` flap-tolerance test.

## TASK-464 — Surface SDK Provider Audio-Drop Count to the Consultation UI (C6-01 sibling, DISCOVERED)

**Status** (line 3, verbatim): `Review — implemented (strict TDD, layered), all layer gates green; awaiting orchestrator review before merge`

**Requirement Analysis** (`## Requirement Analysis`, lines 11–19): TASK-454 fixed the admin-console **playground** hook, but nothing reads the drop count on the real **`@arcaai/vox` SDK consultation path** — the actual browser clinical surface. `StreamingBackendSTTProvider.getDroppedFrameCount()` had zero non-test callers; `STTProcessor.initializeStreamingRemoteProvider` wired `onTranscription`/`onError` but never read drops; `STTProcessor.getStats()` omitted drops entirely. On a real consultation, sustained backpressure silently drops frames and "the clinician signs an incomplete transcript with no indication of loss" — the same defect class C6-01 targeted, still live on the SDK surface.

**Implementation Summary mechanism** (`## Implementation Summary`, lines 46–78) — a full push channel, quoted verbatim from the README:
```
StreamingBackendSTTProvider.onDrop(count)              // packages/stt (provider)
  → STTProcessor.onBackpressureDrop(count)             // packages/stt (processor, re-emit)
    → TranscriptionPipeline emit 'audioDrop'(count)    // vox pipeline
      → PluginManager.callbacks.onAudioDrop(count)     // vox plugin manager
        → useArcaAudio: store.markAudioLost() + store.incrementDroppedFrames()
          → store.audioLostThisSession / audioDroppedFrameCount
            → EXPORTED selectAudioDropped / selectAudioDegraded  (external vox UI reads via useArcaStore)
```
- **Single counter, no double-counting**: only the provider's count is consumed; `SttV2WebSocketClient`'s own `onBackpressureDrop`/`getDroppedFrameCount` (TASK-454's plumbing) is deliberately not subscribed on this path. `SttV2WebSocketClient.ts` was not touched.
- **Session-sticky latch** (mirrors TASK-454): `audioLostThisSession` survives reconnect, clears only on capture start/stop; tenant-switch/logout/security-wipe also reset it.
- External surface: `useArcaAudio()` exposes `droppedFrameCount` + `audioLostThisSession`; `@arcaai/vox` exports `selectAudioDropped` / `selectAudioDegraded` for the real clinical vox UI (an **external, out-of-this-repo** consumer) to read via `useArcaStore(selector)`.

## TASK-470 — Streaming Quality Eval Harness (Theme F · SOTA S1-EVAL)

**What the harness does** (`## Requirement Analysis`, lines 26–43; `## Implementation Summary`, lines 102–121): Extends TASK-455's loss/latency harness with **clinical quality** scoring and a committed **pass/fail regression gate** — the assertion TASK-455 deliberately deferred. It is the "measurement gate" that Theme A1/A2/A3/B/C (including TASK-471) must pass before shipping any ASR/NER change ("measure first").

**Metrics computed** (Metric-definitions table, lines 34–42, and code delivered):
1. **Medical WER** (`medical_wer`) — word error rate of concatenated time-ordered finals vs. fixture ground truth (`*.gt.txt`), case/punct-folded, medical-term-aware normalization. Guardrail, lower = better.
2. **Keyterm recall** (`keyterm_recall`) — fraction of curated clinical keyterms present as a **contiguous span** (strict) in the hypothesis — "the 'did we drop the drug/dose/finding' catcher." Guardrail, higher = better.
3. **Keyphrase recall** (`keyphrase_recall`) — fraction present as an **ordered subsequence** (gaps allowed) — looser match for longer phrases.
4. **Partial-revision rate** (`partial_revision_rate` / `partial_revision.rate`) — reused from the TASK-455 loss harness; fraction of partials that aren't a forward-extension of the prior partial (churn/flicker). The A1 guardrail.
5. **Tentative-visible latency** (`first_partial_ms` / `ttfw_ms`) — reused; the A1 target.
6. **Commit latency P50/P99** (`commit_latency_ms`) — reused via `_stats`; guardrail for A1, target for A2.
7. **Loss** — `seq.gap_count` + `audio_coverage_ratio` — reused; zero-tolerance guardrail.

`build_scorecard` composes all of the above into one JSON artifact; `assert_no_regression` raises on any threshold breach against the committed `streaming_thresholds.json`.
