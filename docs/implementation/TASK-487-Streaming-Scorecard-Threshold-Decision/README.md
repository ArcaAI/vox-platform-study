### Verdict + decisive code evidence (analysis 2026-07-10, code-verified against `fix/2605-review` @ `bc125650`)

**What `partial_revision_rate` actually measures — the decisive fact.** The metric is defined in **`apps/stt-v2/tests/integration/test_streaming_loss_harness.py:340-357`** (`partial_revision_rate`). It counts a "revision" purely from the **full caption `text`** of consecutive partials:

- `:349` — `if not cur.startswith(prev): revisions += 1` — a revision is counted whenever the current partial's **full trimmed text** is not a `startswith`-extension of the previous partial's full text.
- fed at `:428` — `"partial_revision": partial_revision_rate([p.text for p in partials])` — the input is `p.text`, the entire caption string.
- `p.text` source: `_classify` `:249-267`, specifically `:258` `text=str(raw.get("text") or "")`. **`_classify` (`:249-267`) and `MessageRecord` (`:232-241`) never read `stable_chars`/`stableChars`** — the metric is structurally BLIND to the committed/tentative boundary.

So the metric measures surface **(a) — full-caption revision, which includes the tentative tail** — NOT surface (b), committed-text revision. This is exactly the wrong surface for the tentative-tail model.

**The wire DOES carry the committed/tentative boundary the metric ignores** (so the refinement is feasible downstream — the data reaches the harness's own WS client, it's just dropped):

- STT-v2 emits `stable_chars` (committed-prefix length) when LA-2 is active — `schemas.py:166` (`SegmentResult.stable_chars` field) + `:192-193` (`to_redis_dict`, emitted only when set); set at `session_manager.py:1593-1596` (`committed, _tentative = policy.update(result.text); result.stable_chars = len(committed)` — **`result.text` stays the FULL hypothesis**; only the integer boundary is added, the tentative string is discarded and the client re-derives the tail as `text[stable_chars:]`).
- The gateway forwards it onto the WS caption as **`stableChars`** — `packages/applications/src/services/stt/streaming/streamingAudioBridge.service.ts:642-646, 684` (`data.stable_chars` → `{ …, stableChars }`, only when a valid non-negative int).
- SDK/UI consume it — `packages/agentic-sdk-v2/src/core/SttV2WebSocketClient.ts:684-686`; UI renders `text.slice(0, stableChars)` settled (`not-italic text-foreground`) + `text.slice(stableChars)` tentative/ghosted (`packages/ui/src/components/live-transcript/transcript-segment.tsx:178-184`).
- `is_final`/`isFinal` (`_classify:252`) is the only partial/final discriminator the harness reads; `stableChars` (committed-vs-tentative WITHIN a partial) rides the same message and is ignored.

**Why the 0.0→0.82 jump is EXPECTED, not real committed churn:**

1. **It's tail volatility, by construction.** LA-2's *commit* logic is unchanged by TASK-471 (`commit_policy.py` was read-only in that ticket). `LocalAgreementPolicy.update` (`commit_policy.py:61-116`) freezes a committed token position and **only grows the committed prefix while the latest hypothesis keeps agreeing** (`:104-108`); on a contradiction inside the committed region it **rolls back to the last still-agreeing token** (`:100-103`) and "is never silently replaced with different text" (`:66-70`). So the committed region moves monotonically forward except for rare contradiction-rollbacks → committed-region revisions ≈ 0. The churn the full-caption metric sees is the **not-yet-committed tail** being re-transcribed — the exact text TASK-471 renders as provisional/ghosted, i.e. NOT the "caption flicker the user sees" the A1 guardrail meant to catch.
2. **The rise tracks the cadence, not LA-2 activation.** Turning LA-2 on does **not** change `text` (it only ADDS `stable_chars`), so it cannot by itself move a `text`-based metric. The driver is the 1.0→0.4 s cadence: finer cadence re-emits the volatile tail more often → more observed tail rewrites. The A1 baseline `0.0` was captured pre-cadence-drop (TASK-455, `…402` pipeline), so comparing 0.4 s-cadence full-caption churn to it is apples-to-oranges.

**Classification: (a) EXPECTED — metric conflates tentative-tail provisionality with committed churn.** It is NOT (b) real over-churn (the guardrail LA-2 protects — committed text — is untouched and, by the commit invariant above, stays ≈ 0), and it should NOT be resolved as (c) by loosening the threshold (that would blind the guardrail to genuine settled-text churn). Caveat, stated honestly: the CURRENT scorecard can't *empirically* separate committed from tentative revisions because the harness never captured `stable_chars` — the classification rests on (i) the definitional fact that the metric reads full `text`, and (ii) LA-2's unchanged monotonic-commit invariant. The refinement below is exactly what turns this into a measured number and also serves as the (a)-vs-(b) discriminator on recapture.
