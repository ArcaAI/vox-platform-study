**Verdict on the diarizer's current quality.** The `diarization/*` subsystem is **cleanly engineered but dormant, finals-only, and not wired to the clinician end-to-end** — it is not fit to ship as a speaker-attribution capability without the fixes below. *Strengths:* a pure-Python `SpeakerTracker` with zero I/O and correct thread-safety, an `EmbeddingService` ABC with pyannote/speechbrain backends, lazy CPU segmentation, non-fatal preseed, a tenant gate on streaming extraction, and a deliberate + tested finals-only design. *Blocking weaknesses:* OFF by default; the one seeded pipeline that enables it points at a placeholder model; **no speaker label reaches the default admin surface even when diarization is on** (B-01); the core 2-speaker separation has a **cold-start absorption hazard** (B-02); **crash-recovery silently emits `"unknown"` forever** (B-03); and the only accuracy safety-net — segmentation refinement — is **dormant in every seeded config** (B-07). TASK-448's headline ("no labels in the live loop") is **confirmed** for the default surface — but the cause is *dormant + inconsistent + latent-defective*, not *absent*. **AC-2 answer: the embedding-clustering path cannot today be called "clinically-adequate" — there is no accuracy test on real 2-speaker clinical audio, and several code paths mis-attribute before any label is even shown.** ACs 1–8 are satisfied; evidence is in the filled register, per-question verdicts, SOTA delta, and §B2 Build Brief below. **Zero source code changed** (AC-8).

### Finding detail — Critical & top Important (verbatim evidence)

**B-01 — the label contract is fragmented and label-field-less.** The backend serializes only `speaker_id` (`schemas.py:182-184`: `if self.speaker_id: d["speaker_id"] = self.speaker_id; d["speaker_confidence"] = str(round(...))`), and a repo-wide search finds **zero** `speaker_label` occurrences in `apps/stt-v2`. The bridge reads it (`streamingAudioBridge.service.ts:636`: `const speakerId = data.speaker_id || undefined;`) and emits `speakerId` (`:688`). The gateway forwards the object type-erased, so `speakerId` reaches the browser — but the DTO has no label field (`streaming-session.dto.ts:103-138`). The admin frame-51 hook reads only `result.speakerLabel` (`use-live-stt-session.ts:193`), which the SDK client only sets from an inbound `speakerLabel`/`speaker_label` the backend never sends (`SttV2WebSocketClient.ts:715-718`) → `streaming-tab.tsx:218` (`row.speakerLabel ? … : null`) never renders. The one id→label bridge, `useArcaAudio.ts:146` (`speakerLabel: result.speakerId`), is a raw-id copy and is on the *vox `useArca`* path (`consultation-demo-screen.tsx:757`), not the frame-51 tab. The label-forwarding realtime method has no callers. Net: even a perfectly-diarized stream shows nothing on the default admin surface, and where a label does appear it is the raw id, not a clinician/patient role.

**B-02 — cold-start second-speaker absorption.** `SpeakerIdentifier.identify` (`speaker_identifier.py`): `best_id, confidence = self._tracker.compare(embed)`; Case 2 (`confidence >= high_threshold` 0.7) matches; Case 3 (`confidence < low_threshold` 0.4) registers a new speaker *unless at capacity, then falls back to best match* (`:74-80`); **Case 4 (the ambiguous [0.4,0.7) band)** only refines if `enable_segmentation_refinement and self._segmentation_service is not None and samples is not None` (`:86-92`), otherwise falls through to `# Fallback: assign to best match / return SpeakerIdentification(speaker_id=best_id, …, is_new_speaker=False)` (`:128-131`). With `max_speakers=2` and the doctor preseeded, a patient utterance that scores 0.4–0.7 against the doctor is labeled the doctor and **never registered** — and `session_manager.py:510-519` only builds a `SegmentationService` when the pipeline declares an inline segmentation model (none does), so the refinement escape is unavailable. Different-speaker cosine is usually < 0.4 on clean audio (so this often works), but noisy clinical audio, ~5 s clips, or same-gender speakers land in the hazard band; the frequency is unquantified because there is no real-audio test.

**B-03 — recovery destroys speaker state and emits `"unknown"`.** Session creation builds the identifier + preseed gated on `effective_diarization` (`session_manager.py:498-543`); **recovery** rebuilds the worker with `speaker_identifier=None,  # Recovery loses session state` (`:2713`) while still passing `diarization_config=(pipeline_config.diarization …)` (`:2708-2710`). In `inference.py`, `_identify_speaker` returns `(None, None)` when the identifier is None (`:722-723`), then `if diarization_enabled and result.text.strip() and not speaker_id: speaker_id = "unknown"` (`:428-429`), and `schemas.py:182` serializes it (`"unknown"` is truthy). So a resumed session emits `speaker_id="unknown"` on every final for the rest of its life, and `_extract_embedding` still runs (tenant + enabled) only to discard the result.

### SOTA delta (AC-6) — Streaming Sortformer vs embedding-clustering (self-hosted only; 2024–2026)

- **NVIDIA Streaming Sortformer** (arXiv:2507.18446, "Streaming Sortformer: Speaker-Cache-Based Online Speaker Diarization with Arrival-Time Ordering", Interspeech 2025): end-to-end online neural diarizer with an **Arrival-Order Speaker Cache**; configurable latency ≈ **0.32–1.04 s**; ~**80 ms** frame cadence; native up to **4 speakers** (2-spk is the strong regime); reported **CALLHOME 2-spk DER ≈ 6.57 vs pyannote ≈ 9.9**; outputs **per-frame speaker-activity probabilities (T×S)**, not discrete labels (you threshold). ~**117 M params**; GPU (benchmarked RTX 6000 Ada, RTF ~214×); **no working CPU/ONNX path** (open NeMo issue); needs the **NeMo/PyTorch** runtime. HF checkpoints: `nvidia/diar_streaming_sortformer_4spk-v2` (**cc-by-4.0**, commercial-OK), a v2.1 (**NVIDIA Open Model License**), and an **offline v1 (cc-by-nc — NOT for commercial use)**. ~**471 MB** `.nemo`. **Not in our offline HF cache** (`HF_HOME` holds only whisper + silero + the pyannote embedding model).
- **Embedding-clustering** (pyannote/wespeaker/ECAPA — the current path): fundamentally offline/clustering-oriented; for streaming it is threshold-brittle, cold-starts poorly with few embeddings, and degrades on short (~5 s) clips and overlap (the `window="whole"` embedding blends overlapped speakers). pyannote's own online story is weak (diart is community/experimental). B-02/B-06/B-07 are this paradigm's known weaknesses made concrete.
- **Head-to-head (2-speaker streaming):** Sortformer wins on latency (frame-level, ~1 s first label) and accuracy (lower DER) and collapses a multi-stage embed+cluster+segment stack into one model (less model-ops) — at the cost of a heavier GPU/NeMo dependency and a model to stage. Embedding-clustering wins only on *already-deployed footprint* (cached, CPU-capable) and on trivially naming an enrolled speaker via preseed. For HOPE's live clinician/patient case, **Sortformer is the stronger core; keep embedding+preseed for naming.**
- **Peer ambient scribes** (Nuance DAX, Abridge, Nabla, Suki, Ambience): mostly cloud; the transferable, self-hosted-safe pattern is **diarize-then-LLM-role-label** — acoustic diarization yields anonymous Speaker0/1, then an LLM assigns "Clinician"/"Patient" from content. **Self-hosted posture:** no cloud diarization vendor may receive clinical audio; both Sortformer (NeMo, self-hostable) and the current pyannote stack satisfy this — a cloud LLM role-labeler would need de-identified text or an on-prem model.
- **Caveat:** none of the cited DERs are on clinical audio; **in-domain evaluation on a de-identified 2-speaker fixture is required** before trusting any number, and across all systems the dominant error is missed-speech / boundary timing, not confusion — measure both (this is the B2 metric work, item 3).

### What's done well (praise)

- `SpeakerTracker` is pure-Python, zero-I/O, correctly L2-normalized, thread-safe, and thoroughly unit-tested (22 cases incl. the hybrid-scoring math and window eviction).
- Clean abstraction: `EmbeddingService` ABC + pyannote/speechbrain backends selected by model-ID prefix; lazy CPU segmentation; a recursion-depth guard on refinement.
- Deliberate finals-only design with a **tenant gate on streaming extraction** (`inference.py:681`) and **non-fatal preseed** (TASK-296 echo contract) — graceful degradation throughout.
- The TASK-330 no-Qdrant baseline is guarded by a regression test (`test_no_qdrant_vectorstore.py`).
