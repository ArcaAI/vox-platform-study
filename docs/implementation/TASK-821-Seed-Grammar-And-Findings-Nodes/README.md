## 1. The defect

**`agent.grammar` is registered but seeded nowhere.** Lane R (TASK-815 §14) added the node type, the
realtime handler and the Python activity so a clinician would see the partial transcript improve
during a session. Neither ArcaAI graph contains the node, so **the live grammar pass runs for no
tenant today.**

This directly contradicts TASK-815 §14a, which records that item as *"Made to work"*. It was made
*possible*; it was not made to *happen*. The orchestrator repeated that claim to the owner, and it
was wrong — recorded here rather than quietly corrected.

## 2. Second instance, same shape

**`consultation.realtimeSummary` receives an EMPTY transcript in graph mode.** Its `in: transcript`
port is unwired in both seeded graphs — deliberately, because `captureBinding → realtimeSummary`
jumps `extractEntities` — and the seed comment says the activity "resolves what it needs
server-side". The **realtime handler does not**: it passes `boundText(ctx,'in')`, which is `''`.

Confirmed against the committed compiled config: `stage 3: n_realtime <- [n_entities.out->entities]`
only. Pre-existing from the OD-15 work, not introduced by Lane R.

**This one needs a decision, not just an edit:** either a graph rule change (so the transcript can
reach it without bypassing `extractEntities`) or a handler fallback (resolve server-side, matching
what the seed comment already claims). Those are different contracts.

## 3. What "seeded" has to respect
`allPathsPassThrough` (WF-CONS-009) plus the PHI hop (WF-CONS-010) and WF-CONS-012 constrain where a
realtime node may sit. TASK-815 §17 records that `capture → findings → entities` was the ONLY shape
satisfying all three for `agent.important_findings` — expect the same class of constraint here, and
do not assume a free choice of insertion point.

Seeds must be regenerated **by script** — `scripts/regen-arcaai-consultation-workflow-seed.ts` writes
seed 23; `scripts/regen-workflow-definition-seed.ts` prints seed 21's literals and must end
`=== DRIFT: 0 ===`. Never hand-edit a generated file or hand-write a checksum.

## 4. Why this is blocked
TASK-816 Phase 1 regenerates the same two seed files and moves `registryChecksum()`. Two lanes doing
that concurrently would each invalidate the other's regeneration — the collision TASK-815 §13 was
split into one lane to avoid. **Start this only after 816 Phase 1 has merged.**
