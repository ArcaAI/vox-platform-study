**This one needs a decision, not just an edit:** either a graph rule change (so the transcript can

satisfying all three for `agent.important_findings` — expect the same class of constraint here, and
do not assume a free choice of insertion point.

## 7. The derived placement — forced by TWO constraints, not one

Both nodes hang off `n_capture` and rejoin at `n_entities`. §3 was right to expect the §17 class of
constraint; it is actually a PAIR, and the second one is invisible to the validator.

**Constraint 1 — the rule set (`allPathsPassThrough`).** WF-CONS-012 requires every route from
`consultation.captureBinding` to `consultation.synthesize` to cross `consultation.extractEntities`.
So a branch off capture that rejoins anywhere DOWNSTREAM of extraction opens a route around it, and
one that rejoins after synthesis skips the PHI hop (WF-CONS-009) and synthesis (WF-CONS-010).
Rejoining AT extraction is the only shape that satisfies all three. WF-CONS-004 closes the last
escape: a node that rejoined nowhere would fail `REACHES_TERMINAL`.

**Constraint 2 — lane filtering (`buildRealtimeLane`).** It DROPS any binding whose producer is not
itself a `realtime` node. `consultation.phiHop.out` is also `transcript`-typed and would validate,
compile and pass every rule above — and then be **silently unbound at flush time**, reproducing the
exact defect of §2 one layer down. `consultation.captureBinding` is the palette's ONLY realtime
producer of `transcript`, so it is the only legal source.

Together these leave exactly one placement, and it is the one `agent.important_findings` already
has. The consequence is the same too: the optional `entities` hint port stays UNWIRED on both nodes,
because the hints come from `n_entities`, which now runs after them, and an edge back would be a
cycle.

### 7a. A load-bearing claim in the seed was FALSE

`23-arcaai-workflow-authoring.ts`'s module docstring read:

> `captureBinding -> realtimeSummary` is the clearest casualty: it jumps `extractEntities`, and
> WF-CONS-012 refuses it.

It does not. WF-CONS-012 constrains where a branch REJOINS, not whether the edge may exist. The edge
was refused by the rest of the wiring — `n_realtime -> n_terms` carried the summary straight past
extraction — and not by the rule. That sentence is why the port stayed unwired for two tickets, so it
is corrected in place rather than quietly deleted.

## 8. Item 2 — DECISION: fix the GRAPH, not the handler

`n_capture.out -> n_realtime.in`, rejoining at `n_entities`. **The handler fallback was rejected**,
for four reasons in descending weight:

1. **It would delete the property the architecture exists to enforce.** `realtime-executor.ts`'s
   stated rule is that inputs resolve *"by DECLARED PORT — never by an expression the caller happened
   to have in scope"*, and `runGraphLane` promises that *"on a tenant lane whose generation node is
   wired to something else, the prompt follows the wiring instead of silently ignoring it"*. A
   fallback makes the wiring advisory: a tenant who deliberately narrows `in` still gets the whole
   session transcript.
2. **It is unsound against a DEGRADED predecessor.** `resolveBoundInputs` treats an absent key as
   *"contributes nothing. Never a throw, never a fabricated value"*. The handler cannot distinguish
   "authored unwired" from "capture degraded this turn", so the fallback would fabricate a
   transcript precisely when the upstream said it had none.
3. **It does not generalise, and the non-generalisation is the tell.** Four realtime handlers read
   `in`; three (`extractEntities`, `agent.grammar`, `agent.important_findings`) early-return on
   empty. Giving the fallback to only `realtimeSummary` makes one handler special for no stated
   reason; giving it to all four would let NER pull the session transcript regardless of wiring,
   which is the anti-laundering guarantee itself.
4. **The seed comment it would have honoured was wrong anyway** (§7a), and `phiHop`/`suggestions` —
   the other unwired transcript inputs — really are durable nodes whose activities resolve
   server-side. Only `realtimeSummary` was mis-filed among them.

**A second defect fell out of the same fix.** `n_entities.out -> n_realtime.entities` was the node's
ONLY binding, and `RealtimeSummaryHandler` never reads `entities` — so the seeded graph wired the
port the handler ignores and starved the one it reads. Removing it is required twice over: it is a
cycle once the summary is ordered into extraction, and `PLATFORM_REALTIME_LANE` leaves the same port
unwired on purpose because wiring it *"would make the note wait for NER, serialising the two calls"*.
The seeded graphs now agree with the lane they are meant to be at parity with, and the note moves
from lane stage 3 to stage 1.

## 9. Runtime proof — what it does and does not establish

The strongest evidence available from a worktree, and its limits stated rather than glossed.

**What was proven.** The COMMITTED compiled seed is fed to the REAL `buildRealtimeLane` — imported
from `packages/applications` by computed path, the same trick the seed suite already uses for the
engine — and the lane it returns is asserted node by node. Replicating the filter in the test would
have proven only that the test agrees with itself. Both graphs yield:

```
stage 0: n_capture(consultation.captureBinding) <- []
stage 1: n_findings(agent.important_findings)      <- [n_capture.out->in]
      || n_grammar(agent.grammar)                  <- [n_capture.out->in]
      || n_realtime(consultation.realtimeSummary)  <- [n_capture.out->in]
stage 2: n_entities(consultation.extractEntities)  <- [n_findings.next->after, n_grammar.next->after,
                                                      n_realtime.next->after, n_capture.out->in]
```

That establishes: the node EXISTS in both seeded graphs; the lane builder ADMITS it; its `in` binding
SURVIVES lane filtering; its producer is the capture node; and `realtimeSummary.in` — the one input
`RealtimeSummaryHandler` reads — is bound. Since `boundText(ctx, 'in')` returning `''` was the whole
defect, a surviving binding is the property that was missing.

**What it does NOT establish**, and must not be claimed: that a live model call returns useful
corrections, that latency fits the flush budget, or that the console panel renders them. Those need a
running stack (STT → gateway → live-documentation → `apps/text`), which cannot be started safely from
a worktree. **Named follow-up: one live session against the ArcaAI tenant, watching the
`correction-proposals-panel` populate and the running note become non-empty in graph mode.**

### 12a. Why the node needed a bound instruction, not just a presence

`resolveGovernedNodePrompt` reads `config.promptTemplateId` and **throws** when it is absent
(`no_correction_prompt_bound`); the executor turns that into a `degraded` outcome. A seeded node with
no binding would therefore have degraded on every flush — "runs for nobody" in a different costume.
The instruction is a SYSTEM-tenant `PromptTemplate`, the sanctioned platform-default tier
(`PromptTemplate` is a `SYSTEM_SHARED_READ_MODEL`); a tenant with an opinion binds its own id on the
node. It ships no clinical vocabulary — the three categories it names (`spelling`, `medicalTerm`,
`drugName`) are the CLOSED wire contract `verifyCorrectionProposals` enforces at both producers, so
an instruction omitting them would produce proposals the verifier silently discards.
