## Requirement Analysis

User's direct observation after TASK-583/584 shipped: root still has two template files — `.env.example` (generated by `env:sync`, bootstrap floor) and `.env.sample` (hand-assembled, wraps `.env.example`'s content as its first section then appends 9 more files). That's not consolidation; it's a wrapper with duplicated, driftable content.

Fix: eliminate `.env.example` (root) as a standalone tracked file. Fold its content into `.env.sample` as a generated section, produced directly by `pnpm env:sync` (replacing the hand-run assembly script), so `--check` covers the whole file.

## Current State Evaluation

- `env:sync`'s `buildArtifacts()` writes `.env.example` (root, bootstrap floor only) as one of 4 generated TS artifacts.
- The TASK-583 assembly script (a one-off Python file, not part of `env:sync`) reads `.env.example` plus 9 other tracked example files and concatenates them into `.env.sample`, with duplicate-key de-duplication (first occurrence active, later ones commented). It has to be re-run by hand whenever a source changes.
- Nothing reads `.env.example` directly anymore (confirmed in TASK-583/584 — every `cp .env.example ...` instruction was already replaced with `cp .env.sample .env.dev`), so the file's only remaining purpose is being copied into `.env.sample`.
- Tests (`scripts/__tests__/env-sync.test.ts`, `apps/api/src/__tests__/env-port-standardization.test.ts`) assert properties of `.env.example` directly (exact bootstrap-floor key set, ≤60 lines, no keys beyond the floor).

## Implementation Plan

1. **`scripts/env-sync.mts`**: add `renderConsolidatedSample()` that assembles the full `.env.sample` content in-process (bootstrap floor + api/admin-console/tools sections, all in-memory, + the 6 Python services' `.env.sample` files read from disk), porting the TASK-583 script's de-duplication logic (first active declaration wins, later ones commented with a cross-reference). `buildArtifacts()` drops the `.env.example` entry and adds `.env.sample`. The bootstrap-floor content stays testable via an exported getter, without needing to be a standalone file.
2. `git rm .env.example` (root).
3. Update `scripts/__tests__/env-sync.test.ts` and `apps/api/src/__tests__/env-port-standardization.test.ts` to target the new shape (exported floor getter instead of `artifact('.env.example')`; `.env.sample` added to drift/dedup checks).
4. `.gitignore`: drop the root-specific `!.env.example` line (the broader `!**/.env.example` stays, still needed elsewhere).
5. Reference sweep: every doc describing root `.env.example` as an existing file gets updated to describe the bootstrap-floor section of `.env.sample` instead.

## Implementation Summary

All 5 plan steps done.

1. **`scripts/env-sync.mts`** rewritten: `renderRootExample()`'s logic is now internal, exposed via an exported `getBootstrapFloorContent()` getter (no longer written to a standalone file). New `renderConsolidatedSample()` assembles `.env.sample` in-process — bootstrap floor + the 3 in-memory TS sections (`apps/api`, `apps/admin-console`, `packages/tools`) + the 6 Python services' `.env.sample` files read from disk (`readFileSync`) — with de-duplication ported from the original TASK-583 assembly script: the first ACTIVE declaration of a key wins, later ones become `# [duplicate key, see <section> above] # KEY=value` comments. `buildArtifacts()` now returns exactly 6 artifacts (`.env.example` removed, `.env.sample` added); `main()`'s reporting uses `getBootstrapFloorContent()` instead of an artifact lookup.
2. `git rm .env.example` — required `git reset -- .env.example` first to clear a stale staged "AD" (added-in-index/deleted-in-worktree) state before the removal was clean.
3. **Tests retargeted**: `scripts/__tests__/env-sync.test.ts` — `ENV_FILES` narrowed to the 3 TS-generated per-app files; a new `declaredTsSurfaceKeys()` helper re-includes `getBootstrapFloorContent()`'s keys so the turbo.json/dead-keys/size-ceiling checks don't silently lose floor coverage; a new `GENERATED_ENV_ARTIFACTS` list adds `.env.sample` to the placeholders-only/no-active-duplicates/drift checks. All 23 tests pass. `apps/api/src/__tests__/env-port-standardization.test.ts` — section 3 now reads the bootstrap floor via a local `bootstrapFloorContent()` helper that slices `.env.sample` at the `# Source: apps/api/.env.sample` banner (this test file reads files by disk path and doesn't import from `scripts/env-sync.mts`, so a self-contained slice was more appropriate than a cross-package import); the `envFiles` list in the retired-services check swaps `.env.example` → `.env.sample`. **Also fixed in passing**: section 4 (`.env.test` port topology) was unconditionally reading `.env.test`, which TASK-583 (earlier in this same uncommitted body of work) made gitignored+generated — it would ENOENT-crash on any checkout that hasn't run `pnpm setup:test`.
