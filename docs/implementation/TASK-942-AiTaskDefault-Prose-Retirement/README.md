## 1. Requirement Analysis

TASK-881 removed the `AiTaskDefault` table, service, routes, domain trio and descriptor
family; `AiRoutingPolicy` absorbed the plane. TASK-941 R4 repointed the 72 surviving mentions
in the three Python services. This ticket is the TypeScript remainder.

**Two corrections to the handoff that created this ticket, both measured before filing.** When
I flagged this at TASK-941's close I said "~25 mentions, and the OpenAPI one is operator-visible
so it is the one I would do first". Both halves were wrong:

1. **It is 238 source hits across 134 files, not ~25.** The 23 in `apps/api` were the only part
   I had counted; `packages/` carries 215 more.
2. **The OpenAPI hit should probably NOT be changed at all**, let alone first. It reads
   *"Task-specific extras (thresholds and the like), absorbed from `AiTaskDefault.configJson`"*
   — that is PROVENANCE, the same shape as the four hits TASK-941 R4 deliberately kept in
   guardrail. It explains why the field exists. Rewriting it deletes the absorption record
   instead of completing the migration. See OD-1.

### 2.1 The 78 that must not be touched, and why each is untouchable

- **`packages/domains/src/enums/generated/ResourceType.ts:55`** — `AiTaskDefault = 'AiTaskDefault'`
  is a **LIVE enum member**. A Postgres enum value cannot be dropped, and historical `AuditLog`
  rows name it; the wave-3a migration says so explicitly at its line 83. It also carries its own
  `// RETIRED (TASK-881)` note two lines above, which is already the right answer.
- **The three bare `"AiTaskDefault"` entries in `apps/api/openapi.json`** (and the two console
  copies) are that same enum member rendered into the schema — not prose. They disappear only if
  the enum does, which is never.
- **`packages/vox-node/src/resources/admin/audit.ts` ×3** — the same union, in a file that is
  GENERATED by `gen:admin` and must never be hand-edited (`05-nestjs-api.md`).
- **35 hits in `packages/database/src/prisma/db_main/migrations/**`** — committed migrations.
  `02-database-prisma.md` forbids editing them, and TASK-941 R1 measured the nuance: Prisma 7
  flags a comment-only edit on neither `migrate deploy` nor `migrate status`, so the hazard is
  latent rather than immediate — which is a reason to respect the rule, not to test it.
- **`packages/domains/src/entities/generated/core/*Entity.ts`** — generated, and their mentions
  are provenance (`AiRoutingPolicyEntity.ts:43`, `:55`).

facade that no longer exists — e.g. `text-proxy.controller.ts:293` ("AiTaskDefault /
HarnessPolicy. FAIL CLOSED…"), `:548`, `:1354`, `ai-inference.controller.ts:42` ("The NLP routes

`ai-routing-policy-admin.controller.ts:25` and `:40`. A developer reading any of those goes
looking for a table that was dropped.

**The other 96 need judgement, not a pass.** `110` is a candidate count from a keyword filter,
not a verified defect count. In the `ai-routing-policy` tree especially, a mention is usually
explaining what the plane absorbed — which is exactly the thing to preserve.

### 2.3 Why no gate catches any of this

Prose has no reader. `pnpm lint` has nothing to say about a stale noun in a comment, and the one
guard that does exist is a harness test pinning the opposite direction:
`apps/harness/.../test_task881_judge_selection_source.py:12` asserts `"AiTaskDefault" not in
sql` — there the name must STAY, because it IS the assertion. Any sweep has to read for that
shape rather than match on it.
