1. **Your worktree is your only checkout.** Work only in the absolute worktree path your brief names. Never edit the primary checkouts (`~/Desktop/igglo/ARCAAI/hope-v2`, `ALaaSv3.0`, `hope-v2-deployment`) — other sessions use them. Never `git stash`. Never switch branches. Commit on your lane branch only (`task-1045/<lane>`), small logical commits, message `feat|fix|test|docs(task-1045): <what>` + trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. 2. **Own files only.** Touch only the files your brief lists. If you need a change in a file you do not own, stop and put the exact change (file, lines, patch) in your report under "Hand-overs" — the orchestrator applies it.
3. **NO gating tests.** Run ONLY the test file(s) your brief names, RED first (prove it fails for the right reason), then GREEN. Never run a package-wide suite, a directory, `pnpm test`, `pnpm test:unit`, typecheck/lint/build of a whole package you did not modify, e2e, replay-compat, or a full pytest run. A new dependency goes into your report under "Hand-overs" (the orchestrator updates lockfiles). 5. **Running tests.**
   - TS (vitest): `cd <worktree>/<pkg> && npx vitest run <path/to/your.test.ts>` (`pnpm --filter … test -- <filter>` does not filter).

   - If you cannot run your test at all, say so plainly in the report ("verified by static review only") — never claim green.
6. **Shared infrastructure is the orchestrator's.** No `db:push`, `db:migrate`, `test:db:reset`, `docker compose`, `infra:*`, no dev/test API servers, no edits to `.env*`. Exception, DB lane only: a throwaway shadow database named `hope_shadow_1045_<lane>` on the dev Postgres, dropped at the end.

If the contract is wrong or ambiguous, choose the narrowest reading, document it under "Deviations" and continue — do not invent scope.
