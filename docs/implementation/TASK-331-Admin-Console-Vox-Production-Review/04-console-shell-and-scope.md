## 1. Scope & Business Context

The "console shell" is the cross-cutting chrome that materialises the TASK-327 **scope, not visibility** model: one admin menu set for every admin, with per-tenant *data* scoping enforced server-side via `X-Tenant-Id` + CASL, rather than hiding pages per role. Two operating personas:

- **Super/Global admin (global scope)** — operates across many tenants. Gets a tenant **picker**; must pick a tenant before tenant-scoped work and before impersonation.
- **Tenant admin (locked scope)** — pinned to one tenant. Gets a locked **badge**; sees the same menus but scoped data.

The shell comprises: `ScopeSwitcher` (header), `AppSidebar` + `DraggableNavGroup` (re-orderable, persisted admin nav), the auth-store scope predicates (`isSuperAdmin` / `isGlobalScope` / `isAdmin`), `ScopeSyncInit` (cache invalidation on tenant switch), the admin route guards (`RequireAdmin` / `RequireGlobalScope`), and the impersonation tenant-gate on Playground Overview.

The repo map is confirmed: the admin console is `apps/ui-playground` (React 19 / Vite / TanStack Router / Zustand / `@arcaai/ui`); `apps/admin` does **not** exist.

## 5. Solutions & Actionable Plan

### F1 — Tenant-admin 403 on nav-reachable admin pages *(must-fix / must-verify before tenant-admin GA)*

- **Root cause:** the "scope, not visibility" contract was completed on the **frontend** (nav + route guards unified on `isAdmin`) but the **backend** CASL policy for `TENANT_ADMIN` was never widened to match. `tenant-full-access` (`01-policy.ts:71-107`) has no `Department`/`AsrPipeline` rule and only `read`+`update` (not `manage`) on `Tenant`, while the controllers gate with `@CanManage('Department')`, `@Authorize(['manage','AsrPipeline'])`, and `@CanManage('Tenant')`. The controller comments (`tenant.controller.ts:73-87`, `tenant-frontend-config-admin.controller.ts:16-17`) assert the policy admits tenant admins — a comment-vs-seed contradiction.
- **Decision needed (product):** for each page, is the tenant-admin persona *meant* to use it? If yes → widen policy. If no → it must be hidden from the tenant-admin nav too (true visibility gate), not just 403'd.
- **Solution (if intended for tenant admins):** add tenant-scoped rules to `tenant-full-access`:
  - `{ action: 'manage', subject: 'Department', conditions: { tenantId: '${context.tenantId}' } }`
  - a tenant-scoped rule for the audio-pipeline subject (align the controller's `AsrPipeline` subject name with a seeded policy), and
  - `{ action: 'manage', subject: 'Tenant', conditions: { id: '${context.tenantId}' } }` (or relax the three `@CanManage('Tenant')` controllers to `@AuthorizeAny(['manage','Tenant'],['update','Tenant'])` so read+update suffices).
- **TDD (RED→GREEN):** extend `tenant-ability.regression.test.ts` with a TENANT_ADMIN block asserting `can('manage','Department')`, `can('manage','AsrPipeline'|<seeded subject>)`, and `can('manage','Tenant')` (or the relaxed action) are **true** for the seeded `tenant-full-access` linkage. Add an e2e per page asserting a tenant-admin JWT gets **200 scoped data**, not 403, on `GET /admin/departments`, `/admin/audio/pipelines`, `/admin/tenants`, `/admin/tenant-frontend-config`.
- **Layer chain:** Seed (`01-policy.ts`) → (re-seed policies) → PolicyEngine ability (no code change) → controller guards (relax only if not widening policy) → e2e.
- **Verify cmd:** `pnpm test:unit --filter @arcaai/applications` (regression test) and `pnpm --filter @arcaai/api test:e2e` for the per-page 200-vs-403 assertions. *(Not run here — read-only review.)*

### F2 — Prisma Studio admits GLOBAL_ADMIN at nav/route but not backend

- **Root cause:** Studio gated on `isGlobalScope` (super ∪ global) in nav + route, but backend is `manage:all` (super only); design intent (auth-store comment) is super-admin-only.
- **Solution (quick-win):** gate Studio nav (`admin-nav-items.tsx:40`) and route (`studio.tsx`) on a strict `isSuperAdmin()` predicate (add `RequireSuperAdmin`), matching the backend. Keep `RequireGlobalScope` for any genuinely global-but-not-super surface.
- **TDD:** `admin-nav-items.test.ts` — assert `studio` present for super, **absent** for a global-but-not-super ability; guard test for `RequireSuperAdmin`.
- **Verify:** `pnpm --filter @arcaai/ui-playground test`.

### F3 — Decide GLOBAL_ADMIN's fate

- **Root cause:** scope concept added in code without a seeded role or consistent downstream handling.
- **Solution:** EITHER (a) make it real — seed a `GLOBAL_ADMIN` role + policy set, add `GLOBAL_ADMIN` to `canImpersonate` (`user-list.tsx:40`) and the Overview copy; OR (b) drop it from `isGlobalScope`/`isAdmin` until needed. Pick one to remove the half-wired state.
- **Verify:** `auth-store.scope.test.ts`, `user-list-impersonation-gate.test.tsx`.

### F4 — Seed a tenant menu-order default (quick-win)

- Add an `arcaai-admin` / `menuOrder` `GlobalSetting` row per seeded tenant in `11-global-setting.ts` (value = `DEFAULT_ADMIN_MENU_ORDER`) so the TENANT precedence tier is exercised, and/or expose a tenant-default editor. Add a `resolveMenuOrder` test where only `tenantSettings` is present.

### Quick-wins (F5–F8)

- **F5:** in `setTenant`, also clear/refresh `tenantKey` (`set({ tenantId, tenantName, tenantKey: '' })`) so the store stays consistent.
- **F6:** add `routeMeta` entries for the 6 uncovered admin routes in `header.tsx`.
- **F7:** only push `overview` into the Administration group when `isAdmin` (or relabel the group), and move `studio` to the end of `DEFAULT_ADMIN_MENU_ORDER`.
- **F8:** update TASK-327 docs to "11 menus" and extend `admin-nav-items.test.ts` to pin `frontend-pipeline` + `backend-pipeline`.
