## 1. Scope & Business Context

The #1 focus of this review: an admin impersonates a non-admin user (doctor/nurse) to *play and test the SDK playgrounds as that user*, with the impersonated user's preferences shown read-only and the admin's own preferences restored on exit. This is a support/QA capability for a clinical SaaS, so the security posture (tenant isolation, audit, token hygiene) must be HIPAA-conscious.

The full chain crosses five layers: **UI click** (`user-list.tsx`) → **API mint** (`/auth/impersonate`) → **JWT** (`impersonatedBy` + `tenantId` claims) → **CLS** (`JwtStrategy.validate`) → **SDK prefs** (`ConfigManager` + `PersonalizationManager`) → **playground render** (`ImpersonationGuard` + impersonation JWT on every request).

**Short answer:** the happy path **works for a SUPER_ADMIN operating against the seeded `Global` tenant** — impersonate a doctor, all six playground surfaces render and call the API as that doctor, the action is audited, and the token is revoked + dropped on exit. It is **undercut by (a) a seed-data gap that blocks tenant-admin impersonation in 3 of 4 customer tenants, (b) two overlapping preference-isolation systems that race on start/stop, and (c) a half-wired `targetTenantId` that makes a global admin's *selected* tenant irrelevant for multi-tenant targets.**

## 3. End-to-End Flow (numbered, file:line at each hop)

**Start impersonation (in-tab, the happy path):**

1. **Gate** — `UserList` only shows the select column + Start button when `canImpersonate` (SUPER_ADMIN/TENANT_ADMIN) and, for a global-scope operator with no tenant, blocks with "Select a tenant first" (`user-list.tsx:40-48,96-113,300-318`). Defensive re-check on click (`user-list.tsx:192-196`).
2. **UI → SDK** — `handleImpersonate` calls `useAuth().impersonate(selectedUserId)` (`user-list.tsx:203`).
3. **SDK → API** — `useAuth.impersonate` stashes the admin token in `AgenticClient`'s WeakMap (`useAuth.ts:184-186`; `AgenticClient.ts:30,997-1008`), POSTs `/auth/impersonate` with **only** `{ targetUserId }` (`useAuth.ts:179`).
4. **API mint** — `auth.controller.impersonate`: role check SUPER_ADMIN/TENANT_ADMIN (`auth.controller.ts:427-433`), block impersonating a super admin / a peer tenant admin (`:453-459`), resolve tenant from the target's enabled assignments (`:468-482`), **C-1** cross-tenant block for non-super admins (`:487-495`), mint a 15 min JWT carrying `tenantId` + `impersonatedBy: adminUser.id` (`:502-518`), track auth (`:520-525`), return `{ user (incl. tenantId), token, impersonatedBy }` (`:527-540`).
5. **SDK store** — `setOriginalUser(admin)`, `setImpersonatedUser(data.user)`, `updateAccessToken(impersonationJWT)`, `PersonalizationManager.setImpersonationReadOnly(true)` (`useAuth.ts:187-196`).
6. **Playground store** — `useAuthStore.startImpersonation(result.user, result.token, result.user.tenantId)` sets `impersonationToken` + `isImpersonating` and switches `tenantId` to the impersonated tenant, saving `originalTenantId` (`user-list.tsx:211-212`; `auth-store.ts:106-113`).
7. **ConfigManager isolation (TASK-245)** — snapshot admin prefs, `setReadOnly(true)`, fetch `/admin/users/:id/settings` (namespace `arcaai-sdk`), map → `AppConfig`, `loadExternalPreferences(prefs)` (`user-list.tsx:215-247`; `ConfigManager.ts:215-231,236-238`).
8. **Token feed** — `SDKProvider` recomputes the SDK config: during impersonation it hands `impersonationToken` to `AgenticProvider` (`sdk-provider.tsx:47`); `AgenticProvider`'s per-render sync **skips** access-token overwrite while `authImpersonatedUser !== null` so the impersonation JWT set in step 5 is preserved (`AgenticProvider.tsx:710-720`).
9. **JWT → CLS** — every request: `JwtStrategy.validate` checks revocation, builds `UserSession` with `impersonatedBy` + `tenantId`, and writes CLS `user` + `tenantId` from the JWT only (`jwt.strategy.ts:48-84`; `user.session.ts:53-61`). `ContextInterceptor` rejects any divergent `x-tenant-id` header (SEC-J) (`context.interceptor.ts:71-83`).
10. **Audit** — global `ImpersonationAuditInterceptor` sees `user.impersonatedBy` and emits `UserAuthenticated{userId:admin, impersonatedUserId, endpoint, method}` (`impersonation-audit.interceptor.ts:32-67`; registered `app.module.ts:76-79`); `AuditLogService` writes an `IMPERSONATED_ACTION` row with subject + endpoint (`auditLog.service.ts:458-478`).
11. **Playground render** — each per-doctor surface wraps in `ImpersonationGuard`; `useDoctorContext` sets `requiresImpersonation = isAdmin && !isDoctor && !isImpersonating` and `effectiveUserId = impersonatedUser.id` once impersonating (`use-doctor-context.ts:29-45`). Guard renders children → all SDK/API calls now carry the impersonation JWT → backend attributes them to the doctor.

**End impersonation:**

1. **ConfigManager restore** — `setReadOnly(false)` then `restoreUserPreferences(adminSnapshot)` (persists because read-only is now off) (`user-list.tsx:262-269`; `ConfigManager.ts:244-249,318-319`).
2. **SDK/API** — `useAuth.endImpersonation` POSTs `/auth/revoke-impersonation`, pops the admin token from the WeakMap, restores admin token + user, clears impersonation, `setImpersonationReadOnly(false)` (`useAuth.ts:211-237`).
3. **API revoke** — `revokeImpersonation` requires an active `impersonatedBy` (L-3), revokes the JWT `jti` into Redis with a TTL bounded by `exp` (C-4) (`auth.controller.ts:668-693`; `jwt-revocation.service.ts:38-59`). Next request bearing the revoked token 401s at `JwtStrategy.validate` (`jwt.strategy.ts:53-58`).
4. **Reload semantics (H-1)** — `auth-store` persists to `sessionStorage` and `partialize` drops `impersonatedUser/impersonationToken/isImpersonating/originalTenantId` (`auth-store.ts:160-182`), so a refresh evicts the elevated session and the admin token is re-fed (`sdk-provider.tsx:42-48`).

## 5. Solutions & Actionable Plan

**Quick wins (XS–S):**

- **F-3** *(root cause: UI drops the tenant context the backend already supports)* — thread `targetTenantId` from `useAuthStore.tenantId` through `useAuth.impersonate(targetUserId, targetTenantId?)` → POST body. **TDD:** SDK hook test asserts the body carries `targetTenantId`; reuse backend `auth.controller.task295.test.ts:255-271`. **Layer chain:** SDK hook → UI call-site. **Verify:** `pnpm test --filter @arcaai/vox -- useAuth`.
- **F-4** *(root cause: role lists diverge)* — add `GLOBAL_ADMIN` to the backend admin set (`auth.controller.ts:429-431`) and `IMPERSONATION_ROLES`/`canImpersonate` (`useAuth.ts:18`, `user-list.tsx:40`); OR explicitly document GLOBAL_ADMIN as a UI-only alias and stop listing it in `isGlobalScope`/`ADMIN_ROLES`. **TDD:** controller test "GLOBAL_ADMIN impersonates cross-tenant like SUPER_ADMIN". **Layer chain:** API controller → SDK hook → UI. **Verify:** `pnpm test:e2e` auth + `pnpm test --filter @arcaai/ui-playground`.
- **F-8** — swap the impersonation `jti` to `impersonate-${randomBytes(16).hex}` (keep a stable prefix for log filtering). **Verify:** `pnpm build:api`.
- **F-6** — `toast.warning` (or a one-line note in the impersonation card) that "Reloading ends impersonation." **Verify:** component test.
- **F-10** — delete the `atob` fallback in `use-auto-refresh.ts:66-73`; trust the server `data.user.tenantId` (mirror `user-list.tsx:204-211`).

**Structural (M):**

- **F-1** *(root cause: customer tenants seeded admin-only)* — seed ≥1 DOCTOR (+ a department membership to satisfy the login invariant) and ideally 1 NURSE per customer tenant (ArcaAI/4bits/Mumbai), reusing the `GEN_ARCAAI/GEN_FOURBITS/GEN_MUMBAI` departments already defined (`00-constants.ts:173-175`). **TDD:** a seed-assertion/e2e test "each customer tenant has ≥1 impersonatable non-admin user". **Layer chain:** DB seed only (additive — no schema change). **Verify:** `pnpm db:seed` on a scratch DB, then a query/test (no DELETE/DROP).
- **F-2** *(root cause: two isolation systems own the same `ConfigManager.userPreferences`)* — pick ONE owner. Preferred: let `AgenticProvider`'s identity-change rehydrate be the single source of truth and have it fetch the impersonated user's **backend** `arcaai-sdk` settings when `authImpersonatedUser` is set (so the admin's empty local namespace can't win); retire the manual snapshot/loadExternal in `user-list.tsx`, or sequence it strictly *after* the rehydrate via an awaited handshake. **TDD:** an integration test mounting `AgenticProvider`, starting impersonation, and asserting the resolved config equals the impersonated user's backend prefs (not defaults) regardless of fetch ordering; and that admin prefs resolve after end. **Layer chain:** SDK provider + hook. **Verify:** `pnpm test --filter @arcaai/vox -- AgenticProvider impersonation`.
- **F-5** *(root cause: two registrants of a single-slot handler)* — make `useAutoRefresh` the sole `setOnUnauthorized` owner (it is impersonation-aware) and drop the provider's handler, or have the provider delegate. **TDD:** assert exactly one handler is active and that a 401 under impersonation triggers refresh→re-impersonate. **Verify:** `pnpm test --filter @arcaai/ui-playground -- use-auto-refresh`.
