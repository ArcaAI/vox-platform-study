## 1. Scope & Business Context

This cluster covers the two **clinical-configuration** admin surfaces of the Vox/HOPE admin console (`apps/ui-playground`, *not* the non-existent `apps/admin`):

- **(A4) Prompt-template management** — `/admin/prompts` (`apps/ui-playground/src/features/admin/prompts/index.tsx`). A 4-column workspace (Tenants → Prompt Templates → Versions → Detail) for CRUD + versioning of the clinical prompts that drive SMR summarization/DNA analysis across departments. Detail column hosts an inline editor ("Save as New Version"), a **Quality Test** panel (SMR-scored), and a **Usage Analytics** panel.
- **(A5) DNA writing-style dashboards** — `/admin/dna-reports` (`apps/ui-playground/src/features/admin/dna-reports/index.tsx`). An aggregate dashboard strip + a 4-column browser (Tenants → Tenant Users → Report Versions → Detail) for reviewing per-doctor writing-style "DNA" (PHI-derived), inspecting/diffing versions, and editing attributes.

Both routes are gated by `RequireAdmin` (`prompts.tsx:7`, `dna-reports.tsx:7`), which per `auth-store.ts:153-157` admits SUPER_ADMIN, GLOBAL_ADMIN **and** TENANT_ADMIN — i.e. the design intent is that all three roles share the console, with per-tenant/permission scoping enforced server-side (X-Tenant-Id + CASL). The business value proposition is **multi-tenant clinical config**: a global admin picks a tenant and curates that tenant's prompts/styles; a tenant admin self-serves their own tenant.

The backend mounts both under the audited `/admin` prefix: `PromptManagementController` (`@Controller('admin/prompt-templates')`, `@Authorize(['read','PromptTemplate'])`) and `DnaWritingStyleAdminController` (`@Controller('admin/dna-writing-styles')`, `@Authorize(['manage','DnaWritingStyleReport'])`). DNA artifacts are explicitly treated as PHI: even SUPER_ADMIN cannot cross tenants on a report (`dna-writing-style.service.ts:285-296`).

## 5. Solutions & Actionable Plan

**F1 — Admin DNA edit always 428 (Critical) [quick-win]**

- **Root cause:** UI/backend OCC contract mismatch — backend mandates `If-Match`; UI never sends it (the input type doesn't even carry a version).
- **Solution:** Thread the report's `_version` through the edit dialog like the prompt flow does. (a) Add `version?: number` to `DnaReport`/`DnaStyleVersion` (`dna-writing-styles.ts:19-44`) and ensure `DnaReportResponse` exposes `_version`. (b) Add `expectedVersion`/`ifMatch` to `AdminDnaUpdateInput` and forward `ifMatch ? { tenantId, ifMatch } : { tenantId }` in `useAdminUpdateDnaReport` (`dna-reports.ts:102-117`), mirroring `useUpdatePrompt` (`prompts.ts:285-286`). (c) In `AdminEditDialog.handleSubmit`, pass `ifMatch: \`"${report.version}" `(`dna-reports/index.tsx:153-168`).
- **TDD:** RED — extend `__tests__/dna-reports.test.ts` to assert the PATCH carries an `If-Match` header (currently 0 assertions) → fails. GREEN — wire the header. REFACTOR — extract the shared `ifMatch` builder used by both prompt and DNA hooks.
- **Layer chain:** UI hook → admin-client (header already supported, `admin-client.ts:73-75`) → controller (unchanged) → service (unchanged).
- **Verify:** `pnpm --filter @arcaai/ui-playground test -- dna-reports`; e2e `apps/api/tests/e2e/optimistic-locking.spec.ts`.
