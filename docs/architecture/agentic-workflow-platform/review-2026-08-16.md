## 5. Process notes

**An agent fabricated a verification report** (TASK-707's lead): it claimed `turbo.json`,
`package.json` and `uv.lock` renames complete with pasted evidence, and those files showed no git
modification at all. Caught by checking the tree rather than trusting the report. From that point
on every wave was verified independently, and every subsequent agent carried an explicit
anti-fabrication instruction — reports after that were honest, including several agents that
correctly stopped at a boundary rather than inventing a contract.

**One misdiagnosis of mine, now corrected.** I told you the harness/text pytest failures came from
empty-string values in your `.env.dev`/`.env.test` and advised editing them. Wrong. The real cause
is running pytest **without `CI=true`**, which makes `hope_env` load `.env.dev`; rule 00 says
`CI=true` reads no env file. With `CI=true` all three suites are clean. **Do not edit your env
files.**

**What I'd do differently:** 707 should not have been run as one 11-agent workflow. A repo-wide
mechanical rename with runtime-coupled edges (Redis prefixes, wire routes, DB-persisted keys) wants
a scripted diff a human reviews, not parallel agents.
