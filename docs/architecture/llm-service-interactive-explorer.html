Streaming vs. Non-Streaming Flow Mechanics
Detailed breakdown of how the architecture executes, buffers, gates, and bills synchronous vs. Server-Sent Events generation.

Non-Streaming Execution (JSON)

stream: false

Synchronous single-call HTTP lifecycle returning a complete GenerateResponse JSON document.

1. Concurrency Permit:

Acquires a permit on ResizableSemaphore (timeout 30s). Returns 503 if pool saturated.

2. Permit-Dropping Retries:

If provider returns 429, drops concurrency permit during sleep backoff and re-acquires upon retry to avoid capacity starvation.

3. Post-Receive Safety Gate:

Screens the completed text via ExternalGuardrailClient.screen_output(). If rejected, raises 422/503 before caching or returning.

4. Metering & Response:

Gateway calls emitSyncGenerationUsage() immediately upon receiving the response data to credit the Usage Ledger.

Streaming Execution (SSE & Hub)

stream: true

Resumable, disconnected Server-Sent Events architecture powered by GenerationHub and Redis Streams.

1. Detached Producer Task:

Producer runs as an independent asyncio.Task. Dropping the HTTP client socket never cancels generation.

2. Immediate Handshake:

Gateway answers 200 with stream_url. Client connects to GET /tasks/:taskId/stream with Last-Event-ID.

3. Dual-Dispatch Flusher:

Deltas go to subscribers immediately in-memory; BatchFlusher coalesces 16-32 deltas / 25ms to Redis stream via single XADD.

4. Post-Stream Output Gate & Teardown:

Assembled stream screened before terminal frame. If rejected, sends GUARDRAIL_REJECTED error frame. LlmStreamUsageCollector meters usage at stream end.

Two-Phase Medical Guardrail & Safety Plane
How prompts and generated completions are strictly evaluated for clinical intent, safety, and PII containment.

Phase 1: Input Moderation Gate

Runs in generate.py::_apply_guardrail_gate() before any LLM provider invocation.

  • Calls POST /api/medical/validate on Guardrail (:8861).
  • Checks if prompt relates to legitimate clinical/medical encounter content.
  • Fail-Closed Policy: If guardrail is unreachable after bounded retries, raises 503 GuardrailUnavailableError.
  • If classified as non-medical, raises 422 ContentBlockedError (CONTENT_BLOCKED_NOT_MEDICAL).
  • Input guardrail token spend is recorded and returned in guardrail_usage.

Phase 2: Post-Receive Output Gate (TASK-871)

Runs in output_gate.py::gate_completion() on the assembled completion before returning or caching.

  • Calls POST /api/v1/guardrail/screen/outbound on Guardrail (:8861).
  • Screens for toxicity, refusal behavior, and PII leaks against the original prompt context.
  • Non-Streaming: If rejected, raises OutputRejectedError (HTTP 422/503). Output is never cached or returned.
  • Streaming: If rejected, replaces terminal frame with an error frame (GUARDRAIL_REJECTED).
  • Cycle Tripwire: assert_not_in_judge_scope() ensures internal judge queries never trigger recursive guardrail evaluation cycles.
