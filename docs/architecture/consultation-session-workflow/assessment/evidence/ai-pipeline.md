Terminology note: HOPE runs **three parallel consultation pipelines** with materially different safety postures, which matters for almost every finding below:

| Pipeline | Trigger | Default state |
|---|---|---|
| **Legacy BullMQ pipeline** | `TranscriptionCreated` → `SummaryProcessor` → `NerProcessor` (async jobs) | **ON** (the platform default whenever `harnessEnabled=false`) |
| **Harness Temporal loop** (`ConsultationLoopWorkflow`) | Same `TranscriptionCreated` event, routed instead when `harnessEnabled`/`harness.loop.enabled` | **OFF** — kill-switch defaults `false` (`packages/applications/src/services/consultation/consultation-gates.constants.ts:37,48`) |
| **Live-documentation SSE loop** (`LiveDocumentationService`) | Direct STT result-stream subscription while `Consultation_Session_State = Streaming` | **ON** (`LIVE_DOC_ENABLED` defaults `'true'`, `live-documentation.service.ts:449`) |

Most of the reference's *safer* mechanisms (MCP terminology validation, sensor-based dosage/negation checks, groundedness sensors, multi-agent adjudication) live **only** in the Temporal loop, which is off by default. The legacy pipeline and the live SSE loop — both on by default — have materially fewer safeguards. This split is the single most important fact for interpreting every verdict below.

## Pipeline map

The real end-to-end data flow, file paths and hop-by-hop:

1. **Capture** — browser mic → `@arcaai/room` `AudioTrack` → `@arcaai/stt` WebSocket client (`packages/stt/src/websocket/`) → gateway relay `apps/api/src/modules/streaming/stt-ws.gateway.ts` (`relayResult`, :775-800) → `apps/stt` streaming session (`apps/stt/src/stt/streaming/session_manager.py`).
2. **ASR inference** — `apps/stt/src/stt/streaming/inference.py:311-521` runs ASR on every utterance; `if utterance.is_final:` (`:333`, `:484`) gates embedding + diarization to FINAL utterances only. `SegmentResult` (`apps/stt/src/stt/streaming/schemas.py:134-185`) carries `is_final`, `speaker_id`, `speaker_confidence`, `start_time`/`end_time`, `word_timestamps[].confidence` (engine-dependent; **`None` for Whisper**, the default local engine — `schemas.py:141-148`).
3. **Live relay to browser** — `SegmentResult` → Redis Stream (`is_final` as `"1"/"0"`, `schemas.py:194`) → `StreamingAudioBridgeService.projectAndEmitResult` (`packages/applications/src/services/stt/streaming/streamingAudioBridge.service.ts:792`) → `SttWsGateway.relayResult` (`apps/api/src/modules/streaming/stt-ws.gateway.ts:775-800`, drops partials under backpressure, never drops finals) → browser SDK `TranscriptionResult.isFinal` (`packages/stt/src/types/index.ts:456`). Partials are **display-only** here; nothing in this hop persists them.
4. **Session finalize (the only path that persists a transcript)** — `apps/stt/src/stt/streaming/session.py:342-355` `build_transcript_text()` joins `results if r.is_final` ONLY → `_persist_transcript` (`session_manager.py:3178-3213`) → `POST /api/v1/internal/stt/transcript` → `apps/api/src/modules/internal/stt-internal.controller.ts:147` → `packages/applications/src/services/stt/internal/sttInternal.service.ts#createStreamingTranscriptInner` (:395-449) / `#createTranscript` (batch, :297-369). Raw `dto.transcriptText` is written straight into `ContextItem.content` (`:411-417`/`:318-325`), then `encryptContentIntoEntity` (Vault-Transit **at-rest encryption only**, not PHI redaction), then `ConsultationPipelineEvent.TranscriptionCreated` is emitted (`:357`/`:441`).
5. **Auto-pipeline dispatch** — `ConsultationEventHandler.handleTranscriptionCreated` (`packages/applications/src/services/consultation/events/consultation-event.handler.ts:93-257`) branches on `config.harnessEnabled`:
   - **5a. Legacy (default)**: `consultationJobService.createSummaryJob(...)` (:227) → BullMQ `SummaryProcessor` calls TEXT with the **raw, unsanitized** transcript against a tenant `PromptTemplate` (many of which instruct the LLM to write ICD-10 codes as prose — see Finding F4) → emits `SummaryGenerated` → `handleSummaryGenerated` (:267-371) → `consultationJobService.createNerJob(...)` (:334) → BullMQ `NerProcessor.process` (`packages/applications/src/services/consultation/jobs/processors/ner.processor.ts:62-201`) loads `contextItem.content` (raw, :84-99) → `POST {NLP_URL}/api/v1/classify/tokens` (:218-227) → NLP `token_classifier.py` extracts entities + negation/assertion (`apps/nlp/src/nlp/services/assertion.py`) + deterministic ontology-code lookup (`apps/nlp/src/nlp/services/ontology_linker.py`) → `NamedEntity` persisted (`harness-internal.service.ts:454-458` etc.) → `NerExtracted` → `PipelineCompleted`.
   - **5b. Harness Temporal loop (opt-in, off by default)**: `harnessGatewayService.start(...)` (:172-181) → `ConsultationLoopWorkflow` (`apps/harness/src/harness/temporal/workflows.py`) — transcript NER + `persist_entities` (:609-623) → **opt-in** MCP `validate_codes` terminology validation (:633-667, advisory-only, no server registered by default) → institutional RAG retrieval (`apps/harness/src/harness/guides/retrieval/retriever.py`, off by default, no abstention) → optional specialist agents → `adjudicate()` conflict resolution (`apps/harness/src/harness/temporal/models.py:1595-1665`) → note synthesis → sensors (`apps/harness/src/harness/sensors/{computational,inferential}/*.py`) → groundedness/safety scoring.
6. **Parallel real-time work note (Streaming state, independent of 5)** — `LiveDocumentationService.attachSttStream` (`packages/applications/src/services/consultation/live-documentation/live-documentation.service.ts:1569-1599`) subscribes to the same STT result stream, gates on `msg.isFinal` (:1580) and again in `ingestSegment` (:853), debounces (`segmentThreshold`/`idleMs`), runs NLP NER on the **raw, unsanitized** final-segment delta (`nerSourceText = delta || transcript`, :1166) and calls TEXT to regenerate the running SOAP JSON (:1110-1144, with one bounded JSON-repair retry). Guardrail is called here **only** for output groundedness (`this.toolRegistry.guardrail().execute(...)`, :1202-1209) — not PHI sanitization. Publishes `LiveSummaryEventDto` over Redis/SSE to the browser (:1253).
7. **Drain / reconciliation (T15-T17)** — no code implements a Transcription-Agent + NLP-Agent joint "reconcile partials into a final transcript" pass, and no PHI-sanitizer runs on any reconciled transcript before a final note-taking pass (see Finding F3). The "final transcript" is simply the join of already-final segments from step 4.
8. **Review/commit** — outside this lane's primary scope; `summary.service.ts` exposes approve/lock endpoints (:705-885) that block on some flags (:820-822, :868-869) — see Open Questions for wave-2 confirmation of the full approval gate.

### F2b — Uncertainty marks dropped between ASR and every downstream artifact

**Reference requires** (T4, T7): "Every partial segment carries timestamps and speaker attribution. Uncertain text is visibly marked" and this should persist through to review ("uncertainty marks are... propagated into the work note and final summary, or dropped at the first hop").

**Code**: ASR-level confidence exists only transiently on `SegmentResult.word_timestamps[].confidence` (`apps/stt/src/stt/streaming/schemas.py:141-148`) and is engine-dependent (`None` for Whisper). The segment-building functions that produce what actually gets persisted — `session.py:357-397` (streaming) and `apps/stt/src/stt/transcription/dto.py:230-267` (batch) — both emit exactly `{idx, t0Ms, t1Ms, speaker, text, charStart/charEnd}`; confidence is not one of the fields. `packages/applications/src/services/stt/internal/dto/internal.request.ts:27-67` (`TranscriptSegmentInput`) and the persisted `TranscriptSegment` Prisma model (`packages/database/src/prisma/db_main/consultation.prisma:623-667`) both lack a confidence column. `sttInternal.service.ts:129-141` constructs `TranscriptSegmentFactory.CreateTranscriptSegment` with no confidence argument.

The only "confidence" fields that *do* reach a downstream artifact are unrelated signals: `NamedEntity.confidence` (`consultation.prisma:428`) is the NLP/NER model's own entity-extraction confidence, and `live-summary.dto.ts` `confidence?: number` is the TEXT/LLM's self-reported summarization confidence. Neither traces back to ASR uncertainty.

**Failure scenario**: a clinician using the default local Whisper pipeline (word confidence always `None`) dictates a medication name the ASR mis-hears with high acoustic ambiguity. Nothing in the persisted `TranscriptSegment` or the resulting `NamedEntity`/work-note text carries any signal that this span was uncertain — the clinician sees identical-looking text whether the ASR was 99% or 40% confident. **Blast radius**: this directly undermines F6 (no confidence signal exists for a provisional-medication gate to act on) and generally defeats T4/T7's "uncertain text is visibly marked" requirement platform-wide, not just in an edge case.

### F3 — PHI sanitizer never runs before NLP/reasoning consumption

**Reference requires** (T5, T17): guardrail's PHI sanitizer runs on finalized speech BEFORE NLP/Reasoning may consume it, and again on the reconciled transcript before the last note-taking pass.

**Code**: `apps/guardrail/src/guardrail/api/endpoints/guardrails.py:59-111` (`POST /guardrail/analyze`, `type=pii_detection`) is **detection-only** — `GuardrailResponse` (`:36-45`) has no `sanitized_text`/`redacted_text` field; GLiNER (`apps/guardrail/src/guardrail/providers/gliner.py:175-181`) appends an `"pii_detected"` flag to `issues`, never rewrites text. It also **fails open** (`safe=True`) on error (`guardrails.py:97-108`; `gliner.py:212-219`).

More importantly, this endpoint is never called from the transcript pipeline at all. `ner.processor.ts:84-99` loads `contextItem.content` and posts it straight to NLP (`:218-227`) with zero guardrail hop in between. `consultation-event.handler.ts:154-181` forwards the same raw `transcript.content` to both the legacy summary job and the harness `start()` call. The only guardrail call anywhere in `live-documentation.service.ts` (:1202-1209, `GuardrailGroundednessTool`) checks whether the *generated note* is entailed by the source text — output verification, unrelated to PHI, and it never blocks NLP or publication even when it fails (fails to `unverified`, publish proceeds).

A genuine Presidio-backed `PhiRedactor` exists (`apps/harness/src/harness/guards/phi/redactor.py`), but it is scoped exclusively to **cloud-LLM/external-MCP-tool egress** inside the harness generation step (gated by `phi_enabled`/`cloud_egress_providers`, `apps/harness/src/harness/guards/phi/egress.py:59,104,148`) — it never touches the finalized STT segment or the reconciled pre-note transcript, and is a byte-identical pass-through for local/self-hosted providers.

**Failure scenario**: any finalized transcript segment containing PHI (a patient's name spoken aloud, a family member's phone number) flows unredacted into NLP's `/classify/tokens` call and into every TEXT summarization call — the ONLY protection is Vault-Transit encryption of the stored row, which protects data at rest, not the plaintext handed to the model at inference time. **Blast radius**: every consultation, on both the default legacy pipeline and the live SSE loop (the harness loop's egress-scoped redactor doesn't reach this path either).

### F4 — Hallucinated terminology codes: two mechanisms, one of them actively violates the invariant

**Reference requires** (T10, UC-03, UC-16): "No code is emitted without a tool-verified match. Hallucinated codes are forbidden."

**Mechanism 1 (transcript→NER→code, mostly sound but incomplete)**: `apps/nlp/src/nlp/services/ontology_linker.py:1-184` is a **deterministic, offline, ~40-term hardcoded dictionary** (exact-string match after normalization, `:71-87`) mapping common medications/conditions/symptoms/labs/procedures to real SNOMED/RxNorm/ICD-10/LOINC/UMLS codes. Invoked from `token_classifier.py:212-235`. This structurally prevents LLM-style hallucination (a code is either an exact dictionary hit or `None`) but is not "a terminology tool" in the reference's sense — it is a tiny curated table, not a verified live terminology service, and any real-world term outside the ~40 entries silently returns no code.

A genuine MCP terminology-validation integration DOES exist — `apps/harness/src/harness/temporal/workflows.py:195-224,633-667` (`MCP_TERMINOLOGY_TOOL = "validate_codes"`) — but it (a) validates codes **after** they are already persisted (`persist_entities` at `:609-623` precedes the MCP call at `:643-667`), (b) is opt-in per policy (`mcp_tools_enabled`) AND a `workflow.patched()` marker, (c) on failure only sets a run-level `reduced_assurance` flag — it never strips or blocks the already-persisted codes, and (d) has **no terminology server registered anywhere outside unit tests** (`apps/harness/src/harness/tests/unit/temporal/test_mcp_workflow.py` etc.; zero hits in any seed file), so in a default deployment `_select_mcp_server` finds nothing and the block is skipped entirely.

**Mechanism 2 (LLM→note free text, VIOLATED)**: `packages/database/src/prisma/db_main/seed/07-prompt-template.ts` — the seeded, live/APPROVED prompt catalog — instructs the LLM to write ICD-10 codes directly into the note's free-text `assessment` field, with **no tool, no verification, no structured output field**:

```
// :43 — JSON-schema field description for the platform default SOAP template
assessment: { type: 'string', description: 'Primary diagnosis, differentials, severity grading, ICD-10 codes.' }

// :369 (and duplicated at :2394)
'Generate a SOAP-format clinical summary...\n- Assessment: primary diagnosis, differentials, severity grading, ICD-10 codes\n...'

// :561, :698, :768, :1007, :1057, :1158, :1207, :1908 — repeated across department-specific templates (surgery, orthopedics, rheumatology, nephrology, breast/endocrine, ...)
'- Confirmed and provisional diagnosis(es), with ICD-10 code(s) if available'
```

14+ distinct instructions across the catalog ask the model to free-hand ICD-10 codes into `assessment`, a plain `type: 'string'` field — nothing downstream parses or verifies this text (confirmed: no ICD-pattern extraction/parser exists anywhere in `apps/text`, `apps/harness`, `apps/nlp`, `packages/applications`). The harness *does* re-run NER over the LLM-generated note (`workflows.py:824-840`, `note_entities`) but only feeds it to in-memory sensor scoring (`:843-856`) — there is no `persist_entities` call for `note_entities` anywhere in `workflows.py`, so this freehand code text is never re-verified; it simply sits, unlabeled, unverified, in the note the clinician signs.

**Concrete failure scenario**: a clinician using the platform default SOAP template (or any of the 14+ department templates) generates a summary; the model, following its prompt instructions, writes `"Assessment: Community-acquired pneumonia (ICD-10 J18.9)"` in prose. If the actual presentation is closer to J15.9 or J12.9, nothing catches the error — there is no terminology tool consulted, no confidence score, no flag. The wrong billing/diagnosis code ships in the clinician-facing note indistinguishable from a verified one.

**Blast radius**: every tenant using the default or department-specific SOAP templates (the vast majority — the harness/MCP validation path that could catch this is off by default and has no server registered even when on).

### F6 — Confidence gate for terminology/interaction binding is a structural no-op; drug-interaction retrieval does not exist

**Reference requires** (T12.1): "does not bind a terminology code or run interaction retrieval on a guessed name" — implying a confidence gate.

**Code**: `apps/nlp/src/nlp/services/token_classifier.py:220-233` does check `if entity.confidence < floor: continue` before linking — a real gate mechanism — but `linker_confidence_floor` defaults to `0.0` (`apps/nlp/src/nlp/core/config.py:300`, confirmed live at `.env.sample:1556` `NLP_LINKER_CONFIDENCE_FLOOR=0.0`). Since NER confidence is always `>= 0.0`, every entity passes this gate unless an operator manually raises the floor — it ships permissive by default. Worse, this gate operates on the **NLP model's own span-classification confidence**, not ASR transcription confidence (which, per F2b, never reaches NLP at all — `TokenClassificationRequest`, `apps/nlp/src/nlp/schemas/classification.py:38-53`, accepts only `text`). So even a maximally strict floor could never distinguish "the ASR guessed this word" from "the ASR was certain."

Separately, drug-interaction retrieval as a capability **does not exist anywhere in the codebase** (exhaustive grep for `drug_interaction`/`interaction_check`/`InteractionRetrieval` returns zero hits outside this audit's own search). The specific failure mode the reference names ("guessed name triggers interaction retrieval") cannot happen — not because it is correctly gated, but because the feature itself is absent.

### F7 — Retrieval never abstains; no source date/version; no conflict precedence

**Reference requires** (T9): "Low-quality or conflicting retrieval triggers abstention or clarification, not a guessed citation... Guideline snippets... cite version and effective date."

**Code**: a real institutional RAG pipeline exists, but only in `apps/harness` (`apps/harness/src/harness/guides/retrieval/{qdrant_store,retriever}.py`), gated OFF by default (`RetrievalConfig.enabled: bool = False`, `apps/harness/src/harness/core/config.py:160-162`). `packages/database/src/prisma/db_main/knowledge.prisma` (`KnowledgeDocument`/`KnowledgeChunk`) has **no date or version field** — no `publicationDate`, `effectiveDate`, or `guidelineVersion`; only an unrelated encryption `keyVersion`. Tenant scoping IS enforced (`qdrant_store.py:112-146`, `must` filter on `tenant_id` + `status=APPROVED`) — a genuine allowlist even though the word is never used — but there is no "conflict precedence" concept anywhere (grep for "precedence" across the retrieval path returns only unrelated pricing/config-resolution hits).

`apps/harness/src/harness/guides/retrieval/retriever.py:122-155` (`HybridRetriever.retrieve`) takes `ranked[:top_k_rerank]` **unconditionally** — there is no minimum reranker-score threshold, so a weak, marginally-relevant match is attached exactly like a strong one. The only downstream quality signal is a citation-verification judge that checks whether a *specific claim* is entailed by the *chunk it cites* — a hallucinated-citation catch, not a retrieval-quality gate. Nowhere in the repo does "abstain"/"abstention"/"clarification" appear as a retrieval-quality concept (zero hits across `apps/harness`, `apps/text`, `apps/nlp`, `apps/guardrail`, `packages/applications`, excluding tests).

### F8 — Contradictions are not surfaced by default; the one mechanism that exists auto-resolves

**Reference requires** (T6.1, T12.4, UC-09, UC-10): "The synthesizer creates a contradiction, not a resolution... Silently preferring speech or image is forbidden."

**Default-path evidence (VIOLATED)**: `packages/applications/src/services/consultation/prompt/prompt-assembly.service.ts:507-607` concatenates transcript, NER entities, clinician notes, **attachments**, prior-visit summary, and prior draft into one prompt, each in its own `<<<EXTERNAL_DATA section="...">>>` block, with **no conflict-detection instruction** for the attachments/imaging pairing at all. Two narrow precedence rules DO exist but both resolve **silently**, with no discrepancy annotation:
- Prior-visit summary vs. current transcript (`:82-89`): *"if the current transcript does not support it, leave it out rather than carrying it forward"* — silent drop.
- Prior draft vs. transcript (`:579-589`): *"if the prior draft conflicts with the transcript, follow the transcript"* — bare precedence, no surfaced discrepancy.
`live-documentation.service.ts:1933` shows the identical pattern for the live loop: *"keep prior content unless it is contradicted"* — again a silent-overwrite instruction, no flagging.

**The one real mechanism (harness `adjudicate()`, narrow + auto-resolving)**: `apps/harness/src/harness/temporal/models.py:1525-1665` — `AdjudicationConflict`/`AdjudicationRecord`. `adjudicate()` groups **specialist-agent** findings by `output_kind`; when two specialist agents disagree, "the highest-confidence view is accepted... every rejected view is retained alongside it" (`:1611-1616`, `:1639-1656`). This is a genuine "never merge silently" design in the sense that rejected views are retained for audit, but it (a) reconciles multiple LLM specialist agents' own conclusions on the same declared output kind — NOT the reference's inter-source scenario (image finding vs. transcript, historical record vs. current transcript); (b) auto-**resolves** by confidence ranking rather than blocking on a clinician decision, which is exactly what T6.1/T12.4 forbid ("Master/Harness loop does not resolve the conflict"); (c) is gated behind `harness.loop.enabled` (default OFF); (d) publishes only on the ephemeral loop SSE feed (`LOOP_EVENT_ADJUDICATED`), never through `SysEventType` (`packages/domains/src/enums/sysEventType.enum.ts` has zero contradiction/adjudication members) — so it never reaches the audit ledger.

One tenant-specific mitigation exists: the seeded, currently-pinned ArcaAI clinical prompt corpus (`packages/database/src/prisma/db_main/seed/07b-arcaai-clinical-content-v2.ts`, live at `ARCAAI_CLINICAL_APPROVED_VERSION = 3`) contains `RULE 5 — CONFLICT`: *"Where the transcript and the record disagree on a material fact, the transcript governs. Record the transcript value and note the discrepancy once, in place."* This is a genuine anti-silent-merge instruction, but it is (a) scoped to one tenant only, (b) unverified by any automated check, and (c) covers only transcript-vs-prior-record (T1 vs T4) — attachments/imaging are not a listed input to this rule at all.

**Concrete failure scenario (T6.1's own example)**: a patient states "no prior surgery" while an attached CT report describes post-operative clips. For any tenant on the default prompt catalog (i.e., not the one ArcaAI corpus), `prompt-assembly.service.ts` hands the LLM both facts in one prompt with zero instruction to reconcile or flag the disagreement. The model free-generates whichever synthesis it deems most likely — no `contradiction.detected` event, no structured flag, no clinician prompt, no finalization block. This is precisely the "silently prefers one source" failure mode the reference forbids.

### F9b — Only dosage has a real, wired clinical safety check; allergy/laterality/identity are entirely absent

**Reference requires** (T18, US-CL-12): medication, allergy, laterality, dosage, negation, and patient-identity checks before a note is offered for review.

| Check | Verdict | Evidence |

| Dosage | IMPLEMENTED | `apps/harness/src/harness/sensors/computational/numeric_dose.py` — extracts `(value, unit)` tokens, flags any note number/dose absent from the transcript; explicit degrade-not-pass behavior on missing data. |
| Negation | PARTIAL | `apps/nlp/src/nlp/services/assertion.py` is a real ConText/NegEx classifier (PRESENT/ABSENT/HISTORICAL/FAMILY/HYPOTHETICAL) — but it labels NER entity metadata; no sensor/gate was found that flags when the *generated note* flips a transcript's negation polarity (e.g., turns "denies chest pain" into "reports chest pain"). |

### F10 — No DICOM/imaging ingestion; blast radius for UC-02/UC-10

**Reference expects** (T6, UC-02): DICOM/imaging/radiology-report ingestion with authenticated-report preference over model image interpretation. Confirmed ABSENT for the clinical-imaging capability specifically:

- Zero hits for `pydicom` or `.dcm` anywhere in the codebase.
- Generic attachment upload exists: `ContextItemType.ATTACHMENT` (`packages/database/src/prisma/db_main/enums.prisma:233`) with a mimeType-based image check (`context.service.ts:1216`, `mimeType.startsWith('image/')`) — no DICOM parsing, no structured radiology fields.
- A vision-LLM OCR tool exists but is explicitly non-diagnostic: `apps/harness/src/harness/temporal/activities.py:2637-2673` (`vision_extract_text`) sends the image to TEXT with the prompt *"Transcribe all legible text in this clinical image verbatim. Do not interpret, diagnose or summarise."*
- `apps/harness/src/harness/tests/unit/temporal/test_consultation_loop_workflow.py:346-374` explicitly documents `imaging.measure_lesion` as a deliberately **unbacked** placeholder action, used only to prove the workflow correctly *reports* an unregistered action rather than silently dropping it — i.e., imaging interpretation is a documented non-goal today, not an oversight.

**Blast radius for UC-02 (image-assisted consultation)**: a clinician attaching a CT/MRI/DICOM study gets it stored as an opaque blob (or, if a plain image, has only its visible text transcribed) — none of "search for an authenticated radiology report first," "structured findings labeled image-derived," or "reconcile imaging with speech" (UC-02 main flow steps 2-4) exist. **Blast radius for UC-10 (image-vs-speech contradiction)**: since no structured imaging findings are ever produced, there is nothing to compare against speech in the first place — F8's contradiction-detection gap is compounded, not just unaddressed, for the imaging case specifically.

### F11 — ASR fallback is well-built; one silent-drop gap remains for exhausted/unconfigured fallback

**Reference requires** (T4, UC-15): documented fallback ASR; failure visible and logged, never silently dropped.

The fallback mechanism itself is solid: `apps/stt/src/stt/streaming/engine_switch.py` — immediate switch on auth/quota errors (`_IMMEDIATE_SWITCH_ERRORS`, :49), threshold switch after N consecutive failures (`_THRESHOLD_SWITCH_ERRORS`, :92, default 2), one-way auto-switch (never auto-reverts) plus manual bidirectional switch with debounce. A successful switch is genuinely visible end-to-end: `_emit_switch` (:280-317) → Prometheus metric + structured log + `publish_provider_switched` (`redis_streams.py:557`) → relayed over the streaming API → consumed by the browser SDK's message-handling chain (`packages/stt/src/websocket/MessageHandler.ts:90,149` → `providers/BackendSTTProvider.ts:98,116` → `hooks/useSTT.ts:273,335`).

The gap: `apps/stt/src/stt/streaming/session_manager.py:2440-2480` — when `record_failure()` returns `switched=False` (no fallback configured, auto-switch disabled, or the switch itself raises), the code falls to `logger.error("Background inference failed", ...)` (:2474-2480) — **server-side structlog only**; no `publish_error(...)` call is made for this path (that method is used only for rejecting PAUSE/RESUME control frames, confirmed at :2900-2904). The utterance is silently dropped from `session.add_result`. Separately, `apps/stt/src/stt/streaming/inference.py:372-383` — any exception outside the four classified `SWITCHABLE_ASR_ERRORS` types degrades to an empty transcript with only a server log, no client marker distinguishing "silence" from "inference failed."

**Reproduction**: start a streaming session with no `fallback_pipeline_id` configured (or auto-switch disabled); force a non-`SWITCHABLE_ASR_ERRORS` exception (e.g., a decode/runtime error). The session continues; the utterance is dropped or transcribed empty; only server logs record it. From the clinician's screen, a dropped utterance is indistinguishable from a genuine pause in speech.

### F12 — Live/ephemeral work note can publish an empty note with no degradation marker on TEXT failure

**Reference forbids** (T10.1, T16): publishing an empty/truncated/partial note without a degradation marker.

**Durable/final-note path — sound, NOT VIOLATED**: `summary.service.ts:1272-1334` (`callTextService`) retries once against a tenant fallback on primary TEXT failure; if that also fails, it **re-throws** as `BadRequestException` (:1316) — it never substitutes an empty/partial note. Confirmed by `summary.service.text-fallback.task635.test.ts:150-184` (every failure scenario throws).

**Live/ephemeral flush path — VIOLATED**: `live-documentation.service.ts:1090-1092` — `let sections = session.lastPayload?.sections ?? []; let runningSummary = priorNote;` where `priorNote = session.lastPayload?.runningSummary ?? ''`. On TEXT failure, the `catch` block (:1145-1149) sets `textFailed = true` and logs a server-side warning only; `runningSummary`/`sections` are left at whatever `priorNote`/`session.lastPayload?.sections` already were. On a session's **first** flush, `session.lastPayload` is `undefined`, so `priorNote = ''` — a failing first TEXT call publishes `runningSummary: ''`, `sections: []` to the SSE channel with a **fresh** `updatedAt` timestamp (:1249). `textFailed` is tracked internally (logs, admin Redis stats, agent trajectory) but is **never included in `LiveSummaryEventDto`** (`packages/applications/src/services/consultation/live-documentation/dto/live-summary.dto.ts:254-296` has no `textFailed`/`degraded`/`stale` field on the wire contract).

**Reproduction**: point `TEXT_URL` at an unreachable host before starting a live-documentation session; ingest enough final segments to cross the flush threshold. Every flush's `try` throws, is caught, `textFailed=true` is computed but discarded from the outgoing payload. The clinician's live-note panel shows an empty (or, after any prior success, frozen/stale) note refreshing its timestamp on a ~4s cadence with no visual distinction from "the visit just started."

## VIOLATED — ranked (worst first)

1. **F4 — Hallucinated ICD-10 codes via prompt instruction (Critical).** 14+ live, seeded prompt templates instruct the LLM to write ICD-10 codes as unverified prose directly into the clinical note's `assessment` section; the one MCP terminology-verification mechanism built for exactly this is opt-in, post-hoc, non-gating, and has no server registered in any deployment. *Repro*: generate a summary on the default SOAP template or any of ~10 department templates in `seed/07-prompt-template.ts`; the Assessment section will contain a bare ICD-10 code with zero verification trail.
2. **F3 — PHI reaches NLP/reasoning fully unsanitized (Critical).** No PHI-detection or redaction step exists anywhere between a finalized transcript segment and NLP/NER/TEXT consumption; the only PHI-adjacent control (Vault-Transit field encryption) protects storage, not model input. *Repro*: speak a patient/family-member name or phone number during a consultation; trace it into the raw `contextItem.content` posted to `POST {NLP_URL}/api/v1/classify/tokens` (`ner.processor.ts:218-227`).
3. **F8 — Contradictions silently resolved by the LLM in the default path (Critical).** `prompt-assembly.service.ts` hands conflicting sources (attachment vs. transcript, prior record vs. transcript) to the model with no conflict-detection instruction for most pairings; the one structured adjudication mechanism (`adjudicate()`) auto-picks a winner by confidence rather than blocking for clinician review, and is off by default besides. *Repro*: attach a lab/imaging result stating one fact while the transcript states the opposite; the generated note will silently reflect the model's own preference with no `contradiction.detected` event anywhere.
4. **F12 — Empty note publishes silently on first-flush TEXT failure (Critical, scoped to the live SSE preview).** *Repro*: make `TEXT_URL` unreachable before the first flush of a live-documentation session; the clinician's live panel shows an empty note with a live-looking, ticking timestamp and no error indicator.
5. **F9b — Allergy/laterality/patient-identity safety checks are entirely absent (Critical, review-gate impact).** Only dosage has a real, wired check; negation and medication grounding exist but aren't wired as approval gates for their specific failure modes. *Repro*: no code path exists that would catch a note stating the wrong side of a bilateral procedure, or asserting a medication the transcript says the patient is allergic to.
6. **F6 — Confidence gate for terminology binding defaults to a no-op; ASR uncertainty never reaches NLP (High).** `NLP_LINKER_CONFIDENCE_FLOOR=0.0` by default; even a stricter floor could not help because ASR-level confidence is structurally never sent to NLP. *Repro*: any low-confidence ASR span still gets an ontology-code lookup attempt at default settings.
7. **F2b — Uncertainty marks dropped at the ASR→persistence boundary (High).** No confidence field exists on the persisted `TranscriptSegment` model or its DTOs, so "uncertain text visibly marked" is unimplementable downstream of STT today. *Repro*: inspect any persisted `TranscriptSegment` row — there is no column that could carry a confidence/uncertainty value.
8. **F11 — Exhausted/unconfigured ASR fallback silently drops an utterance (High).** *Repro*: session with no fallback configured, force a non-`SWITCHABLE_ASR_ERRORS` exception — utterance vanishes from the transcript with only a server-side log line.
9. **F7 — Retrieval never abstains regardless of match quality (High).** *Repro*: retrieve against a knowledge base with only marginal matches for a query — `retriever.py:151-155` still returns and cites the top-k with no score floor.
10. **F10 — No imaging/DICOM ingestion at all (High, but plausibly a documented non-goal).** *Repro*: attach a CT/DICOM study; it is stored as an opaque blob with zero clinical-image handling.

## Divergences

- **Legacy BullMQ pipeline vs. harness Temporal loop vs. live SSE loop**: three independent code paths implement transcription-to-note synthesis with very different safety postures (see table in Scope & method). Almost every "safer" mechanism found in this audit (MCP terminology validation, dosage/entity-grounding sensors, groundedness scoring via `apps/harness/src/harness/sensors/`, `adjudicate()` conflict handling) lives exclusively in the harness Temporal loop, which is OFF by default (`harness.loop.enabled` kill-switch, `consultation-gates.constants.ts:37,48`). The two paths that run by default — the legacy BullMQ pipeline and the live SSE loop — have materially fewer safeguards (no terminology validation at all in the legacy path's NER call; no sensors; no adjudication).
- **Sync (live SSE) vs. async (BullMQ jobs) failure semantics**: the live SSE path silently degrades to a stale/empty note on TEXT failure (F12); the async/durable path throws and never substitutes content. The same underlying TEXT call has two entirely different failure contracts depending on which pipeline invoked it.
- **Groundedness is real for the *output* of note synthesis but absent for the *input***: `live-documentation.service.ts` runs a genuine, fail-closed NLI groundedness check on the generated note before publishing (`groundedness_nli.py`), but has zero equivalent input-side check (PHI, terminology, contradiction) — the pipeline is asymmetric, verifying what comes out of the LLM far more than what goes in.

## [ADDED] invariants

- **[ADDED] ASR confidence must be uniformly available on the default local engine.** The reference assumes per-span confidence exists to drive uncertainty marking and gating; today it is `None` for Whisper specifically (`schemas.py:141-148`), which is the documented platform default local engine — making T4/T7's "uncertain text visibly marked" structurally unimplementable for most deployments until Whisper gets a confidence proxy (e.g., avg log-prob) wired through.
- **[ADDED] Single-point-of-truth trigger gating needs defense-in-depth.** `ner.processor.ts` and `loop-context-signal.service.ts` contain zero `isFinal`/status checks of their own — they are correct today only because their sole current input (`TranscriptionCreated`/`ContextAdded`) happens to always originate from already-finalized text. `context.service.ts:1412-1425` (`addTranscript`/`addTranscription`) is a dead, unguarded convenience method with no `isFinal` parameter and, notably, no caller anywhere in `apps/api` — if it or the generic `addContext` endpoint were ever wired up for raw/interim ASR text, NER and the loop workflow would fire on unreviewed partials with no downstream check to catch it.
- **[ADDED] Live/ephemeral note payloads need their own degradation marker, not just the final drafting/drain stage.** The reference names degradation markers explicitly for T10.1 (terminology) and T16 (drain), but the live streaming work note (T8, "Streaming" state) has the identical failure mode today (F12) and should carry the same requirement.
- **[ADDED] "Scaffolded-but-inert" is a distinct maturity category worth naming.** The MCP terminology-validation path (F4) and the harness `adjudicate()` mechanism (F8) are both fully-coded, tested, well-commented capabilities that provide zero protection in a default deployment (no server registered / kill-switch off). This reads as "implemented" on a code-search pass but functions as "absent" in production — future audits should score this distinctly from either a genuine implementation or a genuine absence.

## Reference defects

- The reference's T10/UC-03 language ("terminology MCP `search`/`get_concept` tools") implicitly assumes a live, network-reachable terminology server as the only sound design. HOPE's deterministic offline dictionary (`ontology_linker.py`) is a legitimate, arguably compliant-in-spirit alternative for the narrow set of terms it covers (it structurally cannot hallucinate — a lookup is either an exact hit or `None`) even though it never contacts an MCP server. The reference does not anticipate this design, which made scoring Finding F4's Mechanism 1 as a clean PARTIAL rather than VIOLATED — worth reconciling in wave 2 if the reference is meant to bless or reject "curated table" as a valid substitute for "live tool."
- The reference conflates two distinct notions of "safety" under one umbrella (T18's "safety checks: medication, allergy, laterality, dosage, negation, patient identity") without distinguishing them from generic LLM content-safety/harm screening (jailbreak, toxicity, etc.), which HOPE does implement (`apps/harness/src/harness/sensors/inferential/safety.py`, Granite Guardian). A reader could mistake the presence of content-safety screening for coverage of the clinical-fact checks the reference actually names; they are unrelated capabilities.
