# Local app code — the `./…` imports

**Audience:** new to NestJS.
**Scope:** every relative import in `main.ts` and `app.module.ts`.

Anything starting with `./` or `../` is **a file in this repository**. It is not a library, not a Nest feature, and not generated by a CLI. If you cannot find it in `node_modules`, that is expected.

All paths below are relative to `project-hope/apps/api/src/`.

---

## 1. `main.ts` — local imports

### `./app.module`

The root module. `NestFactory.create(AppModule)` builds the whole application from it. If a controller or guard is not reachable from `AppModule`, it does not exist at runtime.

### `./bootstrap/*` — 14 files

These are **not** Nest bootstrap helpers. They are this project's boot-time audits. Each one inspects the route graph after Nest has built it and **throws** if an invariant is broken.

| File | Checks |
|---|---|
| `admin-route-permission-audit.ts` | every route has `@Public()` or a permission decorator |
| `api-key-scope-audit.ts` | every API-key-reachable route declares scopes; `/internal/*` is off the API-key surface |
| `admin-scope-audit.ts` | admin controllers declare no API-key scopes and carry `@ForbidApiKey()` |
| `api-key-surface-audit.ts` | no non-public route is left undeclared |
| `business-plane-apikey-exemptions-audit.ts` | business-plane `@ForbidApiKey()` routes are named exemptions |
| `consent-route-coverage-audit.ts` | every `:patientId` route has consent metadata |
| `service-account-surface-audit.ts` | the third credential class cannot leak into the other two planes |
| `ws-gateway-owner-audit.ts` | every WebSocket gateway is classified for ownership |
| `casl-enforce-reachability-audit.ts` | an enforced CASL pair can actually deny |
| `occ-coverage-audit.ts` | warns (does not throw) about versioned PATCH/PUT missing `If-Match` |
| `genai-content-capture-audit.ts` | production refuses GenAI prompt/response telemetry |
| `jwt-secret-placeholder-audit.ts` | the JWT secret is not the literal placeholder |
| `task-773-admin-scope-map.ts` | the named admin-scope map used by the audits |
| `internal-body-limit.ts` | raises the JSON body limit only for the guardrail internal drain |
| `third-party-public-routes.ts` | the allow-list of public third-party routes |

**Why they exist:** Nest will happily boot a route with no authorization decorator. These functions make that a startup failure instead of a production incident.

### `./config`

`src/config/index.ts` exports `apiEnv()` and the zod schema. This is the **only** validated source of environment values after boot. If a new env var is needed, it goes in `env.schema.ts` / `env.descriptors.ts`, not in a raw `process.env` read.

### `./cors.config`

Builds the Express CORS options. Its rule is unusual: an origin is allowed **only if it is registered in the database**, via `TenantAllowedOrigin`. There is no env allow-list and no wildcard. Extracted from `main.ts` so it can be unit-tested.

### `./crash-handlers`

Registers `uncaughtException` / `unhandledRejection` handlers **before** env loading and Nest creation. Without this, a crash during DI warmup would exit silently. It has two modes: plain stderr JSON before the logger exists, and structured logging after `attachLogger()`.

### `./filters/validation-violations`

Exports `createGlobalValidationPipe()`. It wraps Nest's `ValidationPipe` and adds a structured `violations` list (property path + constraint names, never the submitted value) for the error logger.

### `./global-prefix.config`

Exports `API_GLOBAL_PREFIX = 'api/v1'` and the exclusion options (`/metrics`). Imported — never copied — by the offline OpenAPI emitter, so the document and the live server cannot disagree.

### `./instrumentation`

Starts the OpenTelemetry SDK. Imported for its **side effect**; the entrypoint uses `node --import ./dist/instrumentation.js`, which runs it before any application code.

### `./interceptors`

The barrel for `src/interceptors/`. `main.ts` imports `ETagInterceptor` from here because it is registered with `app.useGlobalInterceptors()` rather than the `APP_INTERCEPTOR` token.

### `./observability/http-response-metrics`

Express-level middleware that counts **every** response, including ones short-circuited before Nest's router (CORS, session, guard 401/429). Registered as the first `app.use`.

### `./observability/prisma-pool-metrics`

Publishes Postgres pool saturation metrics. Must be installed before `NestFactory.create()` so it observes the DI warmup queries.

### `./services`

Exports `GracefulShutdownService` and `startServiceReleaseRegistration`. The first coordinates drain/flush on SIGTERM; the second sends a fire-and-forget heartbeat to the service registry and never blocks boot.

### `./swagger.config`

Builds the OpenAPI document (`createHopeOpenApiDocument`). Extracted from `main.ts` so the security schemes and tags are testable.

| `./vault-prisma.module` | Vault-backed Prisma factory (only active when Vault dynamic creds are on) |

**None of these are framework classes.** They are all project code you can open and read.

## 3. How the local tree is organised

```
apps/api/src/
├── main.ts                  ← entrypoint (process-level)
├── app.module.ts            ← root module (DI graph)
├── instrumentation*.ts      ← telemetry side effect
├── cors.*.ts                ← HTTP policy
├── crash-handlers.ts        ← process-level error handling
├── global-prefix.config.ts  ← route prefix constant
├── request-id.ts            ← CLS/request-id config
├── swagger.config.ts        ← OpenAPI doc builder
├── vault-prisma.module.ts   ← optional Vault DB wiring
├── bootstrap/               ← boot-time audits (run from main.ts)
├── common/                  ← shared SSE/tenant helpers
├── config/                  ← zod env schema
├── database/                ← tenant-context provider (not models)
├── decorators/              ← OCC, API docs, tenant-lock metadata
├── filters/                 ← exception → HTTP envelope
├── guards/                  ← auth, consent, origin, tenant lock
├── interceptors/            ← context, metrics, ETag, maintenance
├── observability/           ← Prometheus metrics
├── openapi/                 ← tag taxonomy + security derivation
├── scripts/                 ← offline emitters (run by CLI, not the server)
├── services/                ← shutdown + service registration
├── shared/                  ← tenant scope, table export, dead base proxy
├── types/                   ← request shape
├── workers/                 ← Vault rotation
├── checkpoint-worker/       ← separate entrypoint module
├── model-publisher/         ← separate entrypoint module
└── modules/                 ← 78 feature modules (controllers + module files)
```

## 4. Framework vs app code: a 10-second check

| Clue | Meaning |
|---|---|
| `@nestjs/...` | framework package |
| `@arcaai/...` | local package under `packages/` |
| `./` or `../` | local file in `apps/api` |
| bare name (`redis`, `zod`) | npm dependency |
| file name ends in `.module.ts` | Nest DI wiring — not business logic |
| file name ends in `.controller.ts` | HTTP routes — should be thin |
| file name ends in `.guard.ts` / `.interceptor.ts` / `.filter.ts` | request lifecycle hook |
| file name ends in `.audit.ts` (in `bootstrap/`) | boot-time invariant check |
| `*.main.ts` | a process entrypoint |
