# Guardrail — content-safety and medical-context validation service

FastAPI service on port 8863 (Python 3.11), package `guardrail`. Guardrail owns **policy**
— criteria, thresholds, taxonomies, verdict shape, and the fail-closed posture — and hosts
**no LLM, no GLiNER runtime, and no MiniCheck weights of its own**. Medical-context judgement
is delegated to `apps/text`'s isolated judge lane; content-safety classification, PII
detection, and groundedness entailment are delegated to `apps/nlp`. Callers are peer
services (`apps/text` posts to `/api/medical/validate`), not the gateway.

## How it works

### Delegation, not inference

Guardrail declares no engine anywhere in its settings. Three delegated calls carry all model
inference:

| Concern | Delegated to | Path |
|---|---|---|
| Medical-context judgement (`/medical/validate`) | `apps/text` judge lane | `POST {TEXT_URL}/api/v1/generate/internal/judge` |
| Content-safety classification + PII spans | `apps/nlp` | `POST {NLP_URL}/api/v1/guard/classify`, `/api/v1/guard/pii` |
| Groundedness entailment | `apps/nlp` | `POST {NLP_URL}/api/v1/guard/entailment` |

`TEXT_URL` (default `http://localhost:8862`) and `NLP_URL` (default `http://localhost:8864`)
are bootstrap transport addresses only — guardrail reads them from the repo-wide names first,
falling back to `GUARDRAIL_V2_TEXT_URL` / `GUARDRAIL_V2_NLP_URL`. There is no `base_url`,
`api_key`, or model default anywhere in guardrail's own config: two moderation models
(`guardrail.safety` for six moderation tasks, `guardrail.pii` for PII spans) and one
groundedness model (`guardrail.groundedness`) are selected and hosted entirely by `apps/nlp`;
the medical judge model is selected and hosted entirely by `apps/text`. The judge lane is
deliberately outside `text`'s own moderation gate and runs on its own semaphore + breaker, so
the safety plane can neither recurse into itself nor starve behind the traffic it protects.

**Fail posture — fail-closed throughout.** A judgement or classification that never rendered
(timeout, peer outage, exhausted retry budget) raises `GuardrailUndeterminedError` /
equivalent, mapped to a 503 on a single-item route and a per-element `undetermined` on a batch
route. It is never silently treated as safe or as `is_medical=true`.

### Per-tenant selection (`core/tenant_config.py`)

The provider/model for `guardrail.validate`, `guardrail.safety`, `guardrail.pii`, and
`guardrail.groundedness` are resolved **per tenant at request time** by a direct, read-only
SQL read of `core."AiRoutingPolicy"` (elected `isDefault` row per `(tenant, taskKey)`) joined
to `core."AiModel"` by `modelId`, cached per `(taskKey, tenantId)` for `GUARDRAIL_CONFIG_CACHE_TTL_S`
seconds (default 60).

- **Cascade is exactly two tiers: request tenant then SYSTEM (`00000000-...`).** A request with
  no `X-Tenant-Id` resolves SYSTEM only. There is deliberately **no** "default tenant" knob —
  the retired `GUARDRAIL_DEFAULT_TENANT_ID` used to widen to the `50000000-...` ("Global")
  customer-tenant playground, serving one customer's safety configuration to every other
  tenant; that knob is gone.
- **Selection fails closed.** An absent row widens to SYSTEM; a `DISABLED` row is a veto
  (`TenantSelectionVetoedError`, 503) rather than a silent fall-through; a DB read failure
  raises `TenantConfigUnavailableError` (also 503) rather than being cached as "no opinion" —
  a stricter tenant must never be silently downgraded to the platform floor.
- **Tuning rides the same row.** `temperature` / `maxTokens` / `timeoutS` come from the
  winning row's `configJson` (the retired `AiRuntimeProfile` table is gone) — no second
  round-trip.
- **Why the exception exists at all.** This is the one sanctioned direct-DB-read exception in
  `06-python-services.md`: guardrail's caller (`apps/text`) is a peer service, not the gateway,
  so there is no gateway-resolved config to inject; and pulling effective config over HTTP
  would put the gateway on guardrail's safety-critical path, closing a
  `gateway -> text -> guardrail -> gateway` cycle.

## Gotchas

- **`GUARDRAIL_DB_CONFIG_ENABLED` is gone.** There is no switch that turns off per-tenant DB
  resolution — it was removed because its only non-default value bricked the service (with no
  env engine left to fall back to, "disabled" meant every selection-dependent route 503'd
  outright). DB config is simply how this service works now.
- **The six engine env prefixes are gone.** `GUARDRAIL_OLLAMA_`, `GUARDRAIL_OPENAI_COMPAT_`,
  `GUARDRAIL_AZURE_`, `GUARDRAIL_BEDROCK_`, `GUARDRAIL_VLLM_`, `GUARDRAIL_LLAMA_CPP_`, and
  `GUARDRAIL_GLINER_` no longer exist anywhere in the settings tree. Do not reintroduce a
  vendor `base_url`/`api_key`/model-id field here — guardrail is policy + HTTP.
- **Host is `GUARDRAIL_V2_HOST`, not `GUARDRAIL_HOST`.** Only `port` has a fleet-wide alias
  (`GUARDRAIL_PORT`, checked before `GUARDRAIL_V2_PORT`); every other `Settings` field
  (`host`, `debug`, `log_level`, `cors_origins`, `gateway_url`) is read under the
  `GUARDRAIL_V2_` prefix only.
- **`GUARDRAIL_REDIS_URL` has a stuttering alias.** `env_prefix="GUARDRAIL_REDIS_"` plus a
  field named `redis_url` would resolve to `GUARDRAIL_REDIS_REDIS_URL`; every operator-facing
  file (including CI) sets the non-stuttering `GUARDRAIL_REDIS_URL`, so both names are
  accepted, canonical name first.
- **Inbound/outbound service auth reads two names.** `INTERNAL_ACCESS_TOKEN` (unprefixed, the
  one shared token every HOPE service accepts and presents) is checked first;
  `GUARDRAIL_SERVICE_TOKEN` is the legacy per-service fallback. Both empty disables the guard
  (local dev / hermetic CI only).
- **There is no "default tenant."** SYSTEM (`00000000-...`) is the sole widening target; do
  not reintroduce a fallback to the `50000000-...` Global playground tenant (see
  `core/tenant_config.py`'s module docstring for the incident this caused before it was fixed).
