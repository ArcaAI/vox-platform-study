36 # TASK-890 — what a FINALIZE reads back. 

37 # 

38 # ``TaskResponse`` has declared ``content`` and ``usage`` since it was written, but the state 

39 # this service persists carried neither, so ``GET /tasks/{id}`` answered ``content: null`` and 

40 # ``usage: null`` for every completed generation and the two gateway benches 

41 # (``finalizePromptTemplateTest``, the draft-agent test finalize) scored an empty string and 

42 # metered nothing. The response model promised a contract the state could not keep. 

43 # 

44 # No new exposure: the deltas are already in the task's Redis stream under the same TTL, so 

45 # this stores the assembled form of bytes that are already there, and expires with them. 

46 content: str | None = None 

47 usage: TokenUsage | None = None 

48 # J3-4 — the METERABLE block, not just the three counts. 

49 # 

50 # ``usage`` is ``TokenUsage``: three integers, no ``endpoint_kind``, no ``byok``, no 

51 # ``cost_basis``, no ``occurred_at``. The gateway ledger refuses to bill from that 

52 # (``parseTextUsageDetail`` returns null without a known endpoint kind, because guessing 

53 # between inclusive and exclusive input arithmetic is a coin flip that lands on an invoice), 

54 # so the draft-agent bench read ``usage_detail`` here, found nothing, and metered NOTHING for 

55 # every run — while the console displayed the token total it had just been handed. 

56 # 

57 # Both terminal paths already BUILD this block for their own response/frame; persisting it 

58 # with the task is the whole fix, and it carries no field the sync response does not already 

59 # return to the same caller. 

60 usage_detail: UsageDetail | None = None
