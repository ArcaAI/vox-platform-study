1"""Outbound resource pools: one HTTP connection pool per upstream, and the one 

2bounded thread pool the Bedrock SDK bridge is allowed to use. 

3 

4Two bottlenecks from the audit meet here, and they are the same bug 

5wearing different clothes: **a shared resource sized for nobody**. 

6 

7* **B-8** — every adapter either built its own transport per request or shared 

8 ONE process-wide `httpx.AsyncClient`. httpx's defaults 

9 (`max_connections=100, max_keepalive_connections=20, keepalive_expiry=5.0`) 

10 are a sensible client library default and a poor egress-proxy default: one 

11 global pool means a saturated vendor starves a healthy self-hosted engine, and 

12 a single `keepalive_expiry` cannot be correct for upstreams whose idle timeouts 

13 differ. So: **one client per upstream** (4.2), each carrying that upstream's 

14 own limits. 

15* **B-3** — Bedrock's boto3 stream is a SYNCHRONOUS iterator, bridged onto the 

16 loop with `run_in_executor(None, ...)`. `None` is asyncio's DEFAULT executor, 

17 `min(32, cpu + 4)` threads, and the bridge holds its thread for the whole 

18 stream. Around 32 concurrent Bedrock streams therefore starve every other 

19 `asyncio.to_thread` caller in the process. The interim fix (4.3) is a 

20 **dedicated, bounded** pool, so Bedrock's ceiling is Bedrock's own. 

21 

22## Where the numbers come from 

23 

24Nothing here is a deployment choice expressed in code. The module-level values 

25are FLOORS in the exact sense `core/runtime_defaults.py` defines: what keeps one 

26wedged upstream from exhausting this process during the window before the control 

27plane has answered. Real operating values arrive from `AiRuntimeProfile` through 

28`GET /internal/effective-config?service=text` and are applied by 

29`apply_pool_policy`, which is the same channel — and the same fail-safe posture — 

30that already moves concurrency, timeouts and vendor quotas. 

31 

32Consequently `apply_pool_policy` follows the two house invariants: 

33 

34* a **negative-cached** snapshot (gateway down) changes nothing at all; 

35* a provider the snapshot does not describe gets the FLOOR, because for a policy 

36 map rebuilt from the snapshot the floor *is* the "no opinion" state. That 

37 differs from `apply_provider_limits`, which must not reset a live semaphore 

38 holding permits — here there is no live state to lose, so the gateway stays 

39 authoritative in both directions. 

40 

41## `keepalive_expiry` is the field that bites 

42 

434.2, stated plainly: an expiry ABOVE the upstream's idle timeout hands you 

44sockets the peer has already reaped, which surface as sporadic, unattributable 

45connection errors under load. The floor is therefore deliberately conservative — 

46low enough to be safe against every upstream, never the intended operating value. 

47Raising it is a per-upstream decision, made on the `AiRuntimeProfile` row for 

48that upstream, by someone who knows that upstream's idle timeout. 

49 

50## ⚠️ This service runs TWO HTTP client libraries, and they are not interchangeable 

51 

52`openai>=3` migrated its transport to **`httpx2`**; `anthropic` is still on 

53**`httpx`**. Both ship a `Limits` / `Timeout` / `http2=` surface with the same 

54shape, which is exactly what makes the mistake easy: handing an `httpx.AsyncClient` 

55to `AsyncOpenAI` is accepted at CONSTRUCTION (it is duck-typed) and only misbehaves 

56later, in the transport, on a real request. mypy is the only thing that catches it, 

57because `openai._base_client` annotates `http_client: httpx2.AsyncClient | None`. 

58 

59So a pooled client is built for a declared `TransportFamily` and the two families 

60are cached separately. Anything reached through the OpenAI SDK — `openai`, 

61`azure-openai`, and every OpenAI-wire self-hosted engine (LM Studio, vLLM) — 

62is `HTTPX2`; Anthropic and the adapters that speak httpx directly are `HTTPX`. 

63"""

124 

125#: Per-upstream ceiling on simultaneously open connections. Inherited from the 

126#: process-wide floor so a single upstream can, in the worst case, use the whole 

127#: budget — a floor bounds damage, it does not portion capacity out. 

128POOL_MAX_CONNECTIONS_FLOOR = HTTPX_MAX_CONNECTIONS

131#: "a TLS handshake per stream" into "a handshake per pool", which is the whole 

132#: point of B-2/B-8 — so the floor is generous, and a deployment SIZES it to the

139POOL_KEEPALIVE_EXPIRY_FLOOR_S = 5.0

144#: assume. "Measure, do not assume" is only enforceable if the default is off.

262def apply_pool_policy(snapshot: EffectiveConfigSnapshot) -> set[str]: 

263 """Move the live pool shapes to match `snapshot`. Returns what changed. 

264 

265 Every upstream whose policy changed has its pooled transport rebuilt AND its 

266 cached SDK clients evicted — a new pool shape is worthless while every client 

267 still holds the old transport. Unchanged upstreams keep their warm pool, 

268 which matters because this runs on the request path. 

269 

270 Never raises: a config refresh may not break a request. 

271 """ 

272 if not snapshot.ok: 

273 # Negative-cached (gateway down) — leave every live value exactly as-is, 

274 # the same posture as `apply_provider_limits`. 

275 return set() 

276 

277 rebuilt: dict[str, PoolPolicy] = {} 

278 bedrock_workers: int | None = None 

279 for profile in snapshot.runtime_profiles: 

280 if not isinstance(profile, dict): 

281 continue 

282 if profile.get("modelSlug") != _PROVIDER_DEFAULT_SLUG: 

283 continue 

284 provider = profile.get("provider") 

285 if not isinstance(provider, str) or not provider: 

286 continue 

287 rebuilt[provider] = _policy_from_profile(profile) 

288 if provider == "bedrock": 

289 bedrock_workers = _positive_int(profile.get("maxConcurrent")) 

290 

291 changed: set[str] = set() 

292 with _LOCK: 

293 for provider in set(rebuilt) | set(_POLICIES): 

294 before = _POLICIES.get(provider, POOL_FLOOR) 

295 after = rebuilt.get(provider, POOL_FLOOR) 

296 if before != after: 

297 changed.add(provider) 

298 _POLICIES.clear() 

299 _POLICIES.update(rebuilt) 

300 for key in [k for k in _CLIENTS if k[0] in changed]: 

301 _CLIENTS.pop(key, None) 

302 

303 _resize_bedrock_executor(bedrock_workers or BEDROCK_STREAM_WORKERS_FLOOR) 

304 

305 if changed: 

306 # The cached SDK clients hold the OLD transports, so they have to go with 

307 # them. Provider-scoped rather than wholesale: an unrelated upstream's 

308 # warm connections are not this change's business. 

309 for provider in changed: 

310 CLIENT_CACHE.evict_provider(provider) 

311 logger.info("text.pool.policy_applied", providers=sorted(changed)) 

312 return changed

315# ── Counting what went over the wire (TASK-959 M-4) ────────────────────────── 

316# 

317# The owner's measurement model wants network consumption per third-party call, 

318# and this module already owns the one seam every pooled adapter passes through: 

319# `_Transport.handle_async_request` sees the request, and `_DrainOnCloseMixin` 

320# sees every response byte the consumer iterates. So the counter goes HERE 

321# rather than in each adapter — a new adapter on the pool is metered because it 

322# is on the pool, not because someone remembered to instrument it. 

323# 

324# What is counted is BODY bytes: `len(request.content)` up, and the sum of the 

325# parts iterated (plus the close-time drain) down. Headers, TLS framing and 

326# HTTP/2 control frames are not counted and not estimated — an invented number 

327# is worse than a documented floor. These are observed on the wire rather than 

328# reconstructed at the application layer, which is the distinction the ledger's 

329# `byteSource` attribute records (`wire` here, `app` where a service can only 

330# report what it handed to an SDK). 

331# 

332# ## Why a contextvar and not a field on the response 

333# 

334# The adapter that needs the number never sees the httpx response: it hands the 

335# request to a vendor SDK and gets a parsed object back. So the record is bound 

336# by the CALLER — one per generation, at the call site that will read it — and 

337# the transport finds it through a `ContextVar`. The value is a MUTABLE object, 

338# which is what makes this safe under asyncio: every task gets its own copy of 

339# the context, but a copy of a reference still points at the one record, so a 

340# transport running inside the caller's task credits the caller's record without 

341# any locking. 

342# 

343# Exactly one thread mutates a given record: the loop thread for every httpx 

344# adapter, or one Bedrock worker thread for a botocore call (`with_byte_counts` 

345# re-binds the record inside that thread, because `run_in_executor` does not 

346# propagate a context). Two threads never share one record, so the `+=` needs no 

347# lock — and a record with no binding is simply not counted rather than being 

348# attributed to whatever ran last. 

349

396@contextmanager 

397def count_provider_bytes( 

398 provider: str, *, funding: str = "platform" 

399) -> Iterator[ProviderByteCounts]: 

400 """Count one logical provider call's body bytes; yields the record. 

401 

402 Restores the PREVIOUS binding with a plain `set` rather than a token 

403 `reset`: an adapter's `generate_stream` is an async generator, so the 

404 enter and the exit can run in different `Context` copies, and 

405 `ContextVar.reset` across two contexts raises. Nesting is not a real 

406 shape here (one provider call per task at a time), so save-and-restore is 

407 both sufficient and unable to fail. 

408 

409 The Prometheus counters are stamped ONCE, on exit, with the totals — a 

410 per-chunk observation would cost a label lookup per token for a number 

411 nobody reads per token. Stamping is best-effort: metering the metering 

412 must never fail a generation. 

413 """ 

414 counts = ProviderByteCounts(provider=provider, funding=funding) 

415 previous = _BYTE_COUNTS.get() 

416 _BYTE_COUNTS.set(counts) 

417 try: 

418 yield counts 

419 finally: 

420 _BYTE_COUNTS.set(previous) 

421 try: 

422 if counts.request_bytes: 

423 PROVIDER_BYTES.labels( 

424 provider=provider, direction="egress", funding=counts.funding 

425 ).inc(counts.request_bytes) 

426 if counts.response_bytes: 

427 PROVIDER_BYTES.labels( 

428 provider=provider, direction="ingress", funding=counts.funding 

429 ).inc(counts.response_bytes) 

430 except Exception as exc: # noqa: BLE001 — telemetry never fails a call 

431 logger.warning("text.pool.byte_metric_failed", provider=provider, error=str(exc))

434def with_byte_counts(fn: Callable[[], _T]) -> Callable[[], _T]: 

435 """`fn`, re-bound to the caller's byte record, for a WORKER THREAD. 

436 

437 `loop.run_in_executor` does not carry a context into its thread (unlike 

438 `asyncio.to_thread`), so a botocore hook firing on a Bedrock worker thread 

439 would find no record and silently count nothing. This closes that gap at the 

440 one boundary that crosses threads, and `reset` IS safe here: the set and the 

441 reset both happen in the worker thread's own context, in order. 

442 """ 

443 counts = _BYTE_COUNTS.get() 

444 

445 def _run() -> _T: 

446 token = _BYTE_COUNTS.set(counts) 

447 try: 

448 return fn() 

449 finally: 

450 _BYTE_COUNTS.reset(token) 

451 

452 return _run

455def _request_body_bytes(request: Any) -> int: 

456 """Body bytes of an outgoing request, without consuming a streaming body. 

457 

458 `Request.content` raises on a request whose body is still a stream (httpx 

459 only materializes it for byte payloads, which is every payload these 

460 adapters send), so `Content-Length` is the fallback and 0 the floor. Never 

461 raises: a body we cannot size is a number we do not have, not a failed call. 

462 """ 

463 try: 

464 content = request.content 

465 except Exception: # noqa: BLE001 — an unread streaming body, nothing more 

466 content = None 

467 if isinstance(content, (bytes, bytearray)): 

468 return len(content) 

469 try: 

470 declared = request.headers.get("content-length") 

471 except Exception: # noqa: BLE001 — a transport double without headers 

472 return 0 

473 try: 

474 return max(0, int(declared)) if declared is not None else 0 

475 except (TypeError, ValueError): 

476 return 0

479# ── Draining close: what actually returns a streamed socket to the pool ────── 

480# 

481# One client per upstream (4.2) buys nothing if every STREAM still ends in a 

482# fresh handshake, and until this wrapper existed every one did — measured at 

483# `1.000 conn/req` by `tests/bench/harness.py --tls --connections-per-request`, 

484# at concurrency 1, with the B-2 client cache and the B-8 pooled transport both 

485# confirmed hitting on every request. 

486# 

487# The drop is one layer below either cache. `openai`'s `AsyncStream.__stream__` 

488# `break`s out of its SSE loop on `data: [DONE]` and then closes the response in 

489# its `finally`. No application bytes remain at that point — but the HTTP 

490# END-OF-BODY marker (the chunked terminator) has not been read, so httpcore 

491# sees a partially-consumed response and tears the connection down rather than 

492# parking it for reuse. Reading those remaining zero bytes to EOF before the 

493# close is the whole fix; the non-streaming path never had the problem because 

494# it reads its body to completion. 

495# 

496# This lives at the TRANSPORT rather than in `openai_compat`, because the seam 

497# that leaks is `Response.aclose()` — by the time the adapter's `async for` 

498# returns, the SDK's `finally` has already closed and the socket is gone. Every 

499# adapter on a pooled client gets the fix for the same reason. 

500 

501#: Bytes the close-time drain will read before giving up. A stream that ended 

502#: normally has ~0 left; a genuinely ABORTED one (consumer disconnected mid 

503#: generation) has the whole rest of the generation, and must NOT be read to 

504#: completion just to save a socket. A floor in the same sense as the pool 

505#: values above: it bounds the cost of the pathological case, it is not a 

506#: tuning knob. 

507DRAIN_ON_CLOSE_MAX_BYTES = 64 * 1024 

508 

509#: Seconds the same drain may take. The normal case completes in one already 

510#: buffered read; anything slower is an abort wearing a drain's clothes. 

511DRAIN_ON_CLOSE_TIMEOUT_S = 0.25

514class _DrainOnCloseMixin: 

515 """Read a response body to EOF (bounded) before closing it. 

516 

517 Mixed into each HTTP family's own `AsyncByteStream` — httpx asserts the 

518 transport hands back one of ITS base class, and the two families are not 

519 interchangeable (module docstring). 

520 

521 Also the INGRESS counter (TASK-959): every response byte a consumer sees 

522 passes through `__aiter__`, and the bytes the close-time drain swallows were 

523 delivered too, so both are counted. The record is the one captured when the 

524 REQUEST was made, not the one bound when a chunk happens to arrive — a 

525 streamed response outlives nothing here, but capturing it removes the 

526 question. 

527 """ 

528 

529 def __init__(self, inner: Any, counts: ProviderByteCounts | None = None) -> None: 

530 self._inner = inner 

531 self._iterator: Any = None 

532 self._at_eof = False 

533 self._counts = counts 

534 

535 def _count(self, size: int) -> None: 

536 if self._counts is not None: 

537 self._counts.add_response(size) 

538 

539 async def __aiter__(self) -> AsyncIterator[bytes]: 

540 # Keep the iterator: a consumer that `break`s leaves it SUSPENDED rather 

541 # than closed, which is exactly what makes the close-time drain possible. 

542 self._iterator = self._inner.__aiter__() 

543 async for part in self._iterator: 

544 self._count(len(part)) 

545 yield part 

546 self._at_eof = True 

547 

548 async def aclose(self) -> None: 

549 try: 

550 if not self._at_eof and self._iterator is not None: 

551 await self._drain() 

552 finally: 

553 # The close must happen even if the drain is cancelled or raises — 

554 # never leak a connection trying to save one. 

555 await self._inner.aclose() 

556 

557 async def _drain(self) -> None: 

558 read = 0 

559 try: 

560 async with asyncio.timeout(DRAIN_ON_CLOSE_TIMEOUT_S): 

561 async for part in self._iterator: 

562 read += len(part) 

563 self._count(len(part)) 

564 if read >= DRAIN_ON_CLOSE_MAX_BYTES: 

565 return 

566 except Exception: 

567 # A drain is an optimisation. Timing out, or a transport that 

568 # refuses to be resumed, costs a handshake — never a request. 

569 return

572def _draining_transport(base_cls: Any, family_module: Any) -> Any: 

573 """An `AsyncHTTPTransport` for one family whose responses drain on close. 

574 

575 The same wrapper carries the TASK-959 byte counters: the request body is 

576 sized here (before the socket, so a failed send still counts what was 

577 offered) and the response stream is handed the record it must credit. 

578 """ 

579 

580 class _Stream(_DrainOnCloseMixin, family_module.AsyncByteStream): 

581 pass 

582 

583 class _Transport(base_cls): 

584 async def handle_async_request(self, request: Any) -> Any: 

585 counts = current_byte_counts() 

586 if counts is not None: 

587 counts.add_request(_request_body_bytes(request)) 

588 response = await super().handle_async_request(request) 

589 response.stream = _Stream(response.stream, counts) 

590 return response 

591 

592 return _Transport

599def _build_client( 

600 provider: str, policy: PoolPolicy, family: TransportFamily, timeout_s: float 

601) -> httpx.AsyncClient | httpx2.AsyncClient: 

602 want_http2 = policy.http2 

603 if want_http2 and not http2_supported(): 

604 logger.warning( 

605 "text.pool.http2_unavailable", 

606 provider=provider, 

607 detail="policy requests HTTP/2 but the 'h2' extra is not installed; " 

608 "negotiating HTTP/1.1", 

609 ) 

610 want_http2 = False 

611 

612 # `limits` and `http2` go to the TRANSPORT, not the client: an `AsyncClient` 

613 # given an explicit transport ignores both, so passing them twice would read 

614 # as configuration that is in fact inert. 

615 if family is TransportFamily.HTTPX2: 

616 return httpx2.AsyncClient( 

617 timeout=httpx2.Timeout(float(timeout_s)), 

618 transport=_HTTPX2_DRAINING_TRANSPORT(limits=policy.limits2(), http2=want_http2), 

619 ) 

620 return httpx.AsyncClient( 

621 timeout=httpx.Timeout(float(timeout_s)), 

622 transport=_HTTPX_DRAINING_TRANSPORT(limits=policy.limits(), http2=want_http2), 

623 )

626def pooled_http_client( 

627 provider: str, 

628 *, 

629 timeout_s: float, 

630 family: TransportFamily = TransportFamily.HTTPX, 

631) -> Any: 

632 """The ONE transport for `(provider, family)`, built from the current policy. 

633 

634 One client per upstream (4.2). Memoized on `(policy, timeout)` so a policy 

635 change or a control-plane timeout push produces a new pool while an unchanged 

636 refresh keeps the connections warm — rebuilding on every refresh would undo 

637 the reuse this module exists to create. 

638 

639 Returns `Any` deliberately: the concrete type is `httpx.AsyncClient` or 

640 `httpx2.AsyncClient` depending on `family`, and both SDKs annotate their own. 

641 A union return would push a cast into every adapter and buy nothing, because 

642 the family an adapter passes is fixed at its call site. 

643 """ 

644 policy = pool_policy_for(provider) 

645 bucket = int(timeout_s) 

646 cache_key = (provider, family) 

647 with _LOCK: 

648 cached = _CLIENTS.get(cache_key) 

649 if cached is not None and cached[0] == policy and cached[1] == bucket: 

650 return cached[2] 

651 

652 client = _build_client(provider, policy, family, timeout_s) 

653 _CLIENTS[cache_key] = (policy, bucket, client) 

654 return client

659 

660 The transports are dropped rather than closed: a request may still be

663 """

672def bedrock_stream_executor() -> ThreadPoolExecutor: 

673 """The dedicated, bounded pool the Bedrock stream bridge runs in. 

674 

675 Never asyncio's default executor. The bridge holds a thread for the entire 

676 duration of a stream, so sharing the default pool means ~32 concurrent 

677 Bedrock generations stall every other `asyncio.to_thread` caller in the 

678 process — a ceiling Bedrock imposes on everyone else. A dedicated pool makes 

679 Bedrock's ceiling Bedrock's own. 

680 """ 

681 global _BEDROCK_EXECUTOR 

682 with _LOCK: 

683 if _BEDROCK_EXECUTOR is None: 

684 _BEDROCK_EXECUTOR = ThreadPoolExecutor( 

685 max_workers=BEDROCK_STREAM_WORKERS_FLOOR, 

686 thread_name_prefix=BEDROCK_STREAM_THREAD_PREFIX, 

687 ) 

688 return _BEDROCK_EXECUTOR

691async def run_in_bedrock_executor(fn: Callable[[], _T]) -> _T: 

692 """Await one blocking Bedrock SDK call on Bedrock's own threads. 

693 

694 The `asyncio.to_thread` replacement for the NON-streaming path. It is the 

695 same defect as B-3, one call shorter: a `converse` blocks its thread for the 

696 whole generation — seconds, not milliseconds — so on the default executor a 

697 burst of non-streaming Bedrock traffic starves every other `to_thread` caller 

698 exactly as the streams do. 

699 

700 Living here rather than at the call site keeps ONE place that knows where 

701 Bedrock's blocking work runs, which is also what stops the boundary drifting 

702 back to the default executor one edit at a time. 

703 """ 

704 return await asyncio.get_running_loop().run_in_executor( 

705 # `with_byte_counts` is what keeps the botocore byte hooks (TASK-959) 

706 # attributable: the record lives in a contextvar and `run_in_executor` 

707 # does not carry a context into its thread. 

708 bedrock_stream_executor(), 

709 with_byte_counts(fn), 

710 )

713def _resize_bedrock_executor(workers: int) -> None: 

714 """Adopt the control plane's Bedrock concurrency as the thread ceiling. 

715 

716 Applied IN PLACE. `ThreadPoolExecutor` reads `_max_workers` when deciding 

717 whether to spawn on submit, so raising it takes effect immediately; the pool 

718 is never swapped out, because each of its threads owns a live generation. 

719 

720 Lowering it is recorded but frees no thread: `ThreadPoolExecutor` workers do 

721 not idle out. That is a bounded, deliberate limitation of the INTERIM fix — 

722 the structural fix (4.3: SigV4-signed direct HTTP over the shared httpx 

723 client) removes the threads entirely and is explicitly out of this lane. 

724 """ 

725 executor = bedrock_stream_executor() 

726 with _LOCK: 

727 if executor._max_workers != workers: 

728 executor._max_workers = workers 

729 logger.info("text.pool.bedrock_workers_applied", workers=workers)
