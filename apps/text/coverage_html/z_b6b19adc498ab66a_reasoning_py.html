1"""One neutral reasoning posture, ten engine vocabularies (TASK-970). 

2 

3An admin turns "Enable reasoning" off on an agent. The posture resolves 

4correctly on the gateway, travels here on ``GenerateRequest.reasoning`` — and 

5then has to become something an engine understands. There are ten engines and 

6no two spell it the same way: 

7 

8=============== ========================================================= 

9adapter what "off" actually is on that wire 

10=============== ========================================================= 

11openai / azure ``reasoning_effort: "none"`` 

12openai_compat an effort rung only — no off value a generic server promises 

13lmstudio the same; LM Studio documents low|medium|high and no off 

14vllm ``chat_template_kwargs: {"enable_thinking": false}`` 

15ollama ``think: false`` 

16anthropic ``thinking: {"type": "disabled"}`` (thinking is opt-IN) 

17vertex ``thinking_config.thinking_budget = 0`` 

18llama.cpp nothing — the native ``/completion`` endpoint has no such knob 

19bedrock nothing normalized — Converse passes a free-form Document 

20 through to each model family's OWN vocabulary 

21=============== ========================================================= 

22 

23Before this module the posture reached THREE of those ten: only 

24``openai_compat`` (and its two subclasses) read ``request.extra`` at all, and 

25the posture rode along as a pre-rendered OpenAI ``reasoning_effort``. The other 

26seven dropped it with no record, while the console told the admin *"the engine 

27is instructed not to reason and reasoning tokens are never billed"*. 

28 

29**The three rules this module exists to hold.** 

30 

311. *Declare, don't drop.* Every adapter carries ``reasoning_support`` / 

32 ``reasoning_parameter`` / ``reasoning_effort_parameter``, pinned against the 

33 committed cross-language contract 

34 ``tests/contracts/reasoning-posture.fixture.json`` by 

35 ``test_task970_reasoning_posture.py``. A new adapter that declares nothing 

36 fails that test — default-deny, exactly like ``CredentialPosture``. 

37 

382. *Unenforceable is LOGGED, never silent and never fatal* (owner decision, 

39 2026-09-13). An engine that cannot express the posture sends nothing, 

40 records provider + model + the posture on the generation's telemetry, and 

41 the call RUNS. No 422: a tuning knob must not become an outage risk on a 

42 provider swap. The defect being fixed is the silent drop, so the fix is a 

43 RECORD — not an error. 

44 

453. *Never approximate OFF onto a low effort.* That lossy mapping is what the 

46 contract was written to remove; re-introducing it one layer down would just 

47 move the lie. An adapter that cannot say "off" says so. 

48"""

64class ReasoningSupport(StrEnum): 

65 """What an ADAPTER can express — not what a vendor could theoretically accept. 

66 

67 The distinction is load-bearing. Bedrock's Converse API *can* carry a 

68 reasoning directive, but only inside ``additionalModelRequestFields``, a 

69 free-form passthrough into the bound model's own vocabulary — which differs 

70 by family and generation, and where a key the family does not know is a 

71 ValidationException, i.e. a failed generation. An adapter that cannot render 

72 the posture SAFELY for every model of its engine declares ``UNSUPPORTED`` 

73 and records, rather than guessing and occasionally taking generation down. 

74 """ 

75 

76 #: A true off-switch this adapter renders. ``reasoning_effort_parameter`` 

77 #: says whether it can also drive an effort dial. 

78 NATIVE_OFF = "native-off" 

79 #: An effort can be expressed but OFF cannot. ``enabled: false`` is RECORDED, 

80 #: never approximated onto a low effort (rule 3 above). 

81 EFFORT_ONLY = "effort-only" 

82 #: The transport cannot express the posture at all — log and proceed. 

83 UNSUPPORTED = "unsupported" 

84 

85 

86#: The engine expresses no part of the posture (``UNSUPPORTED`` adapters). 

87REASON_ENGINE_CANNOT_EXPRESS = "engine_cannot_express_posture" 

88#: The engine has an effort dial but no off value this adapter can promise. 

89REASON_OFF_NOT_EXPRESSIBLE = "off_not_expressible" 

90#: "On" landed, but the named budget has no rung in this engine's vocabulary. 

91REASON_EFFORT_NOT_EXPRESSIBLE = "effort_not_expressible" 

92 

93#: structlog event name — one dotted name so a Loki query finds every engine. 

94UNENFORCEABLE_EVENT = "text.reasoning.unenforceable"

97def posture_to_render(request: GenerateRequest) -> ReasoningPosture | None: 

98 """The posture this adapter must render, or ``None`` to send nothing. 

99 

100 ``None`` has two causes and neither is an error: 

101 

102 * the request carries no posture — nobody had an opinion at any tier, so the 

103 engine decides and nothing is synthesized here; 

104 * the caller PINNED the raw ``extra.reasoning_effort`` ride-along. CALLER 

105 WINS, per key (the rule ``TextRequestEnrichmentService`` documents), so the 

106 adapter renders nothing of its own and the pin travels exactly as far as it 

107 does today — through ``extra_body`` on the OpenAI-compatible family, and 

108 nowhere else. A call site that pins the raw key is not second-guessed. 

109 """ 

110 if request.extra and request.extra.get("reasoning_effort") is not None: 

111 return None 

112 return request.reasoning

115def record_unenforceable( 

116 *, 

117 provider: str, 

118 model: str, 

119 posture: ReasoningPosture, 

120 reason: str, 

121) -> None: 

122 """Record a posture the engine could not honour. NEVER raises. 

123 

124 Three places, because the three readers are different people: a structlog 

125 warning for whoever is reading this generation's logs, a span attribute so 

126 the trace of the call that was over-billed says why, and a counter so 

127 "which engines are quietly ignoring our admins?" is a dashboard question 

128 rather than an archaeology exercise. 

129 """ 

130 logger.warning( 

131 UNENFORCEABLE_EVENT, 

132 provider=provider, 

133 model=model, 

134 reasoning_enabled=posture.enabled, 

135 reasoning_effort=posture.effort, 

136 reason=reason, 

137 ) 

138 span = trace.get_current_span() 

139 span.set_attribute("gen_ai.request.reasoning.enabled", posture.enabled) 

140 if posture.effort is not None: 

141 span.set_attribute("gen_ai.request.reasoning.effort", posture.effort) 

142 span.set_attribute("gen_ai.request.reasoning.unenforceable", reason) 

143 REASONING_UNENFORCEABLE_TOTAL.labels(provider=provider, model=model, reason=reason).inc() 

144

146def record_unsupported_posture( 

147 request: GenerateRequest, *, provider: str, model: str | None 

148) -> None: 

149 """The whole body of ``_apply_reasoning`` for an ``UNSUPPORTED`` adapter. 

150 

151 Sends nothing (there is nothing to send) and records the posture that could 

152 not be honoured. An absent posture records nothing — there was no intent to 

153 fail to honour. 

154 """ 

155 posture = posture_to_render(request) 

156 if posture is None: 

157 return 

158 record_unenforceable( 

159 provider=provider, 

160 model=model or "", 

161 posture=posture, 

162 reason=REASON_ENGINE_CANNOT_EXPRESS, 

163 )

166def apply_openai_wire_reasoning( 

167 kwargs: dict[str, Any], 

168 request: GenerateRequest, 

169 *, 

170 provider: str, 

171 model: str | None, 

172 off_is_expressible: bool, 

173) -> None: 

174 """Render the posture onto the OpenAI chat-completions wire. 

175 

176 ``reasoning_effort`` is a typed parameter of the pinned SDK 

177 (``openai==3.1.0``: ``Literal['none','minimal','low','medium','high', 

178 'xhigh','max']``), so it goes in as a first-class kwarg rather than riding in 

179 ``extra_body``. 

180 

181 ``off_is_expressible`` is the one thing that differs across the five 

182 OpenAI-wire adapters, and it is derived from the declared 

183 ``reasoning_support`` at each call site rather than restated here. 

184 ``'none'`` is a genuine rung of that literal — but only ``openai`` and 

185 ``azure_openai`` talk to a server that is guaranteed to know it. A generic 

186 OpenAI-compatible server (and LM Studio, whose docs list only 

187 low|medium|high) may reject an enum value it has never heard of, and a 400 

188 is a failed generation — so those adapters record OFF instead of guessing. 

189 

190 "On" with no named effort deliberately sends NOTHING: this wire has no 

191 on-flag separate from the effort dial, and a reasoning model reasons by 

192 default, so "on, engine picks the budget" IS the absence of the parameter. 

193 """ 

194 posture = posture_to_render(request) 

195 if posture is None: 

196 return 

197 if posture.enabled: 

198 if posture.effort is not None: 

199 kwargs["reasoning_effort"] = posture.effort 

200 return 

201 if off_is_expressible: 

202 kwargs["reasoning_effort"] = "none" 

203 return 

204 record_unenforceable( 

205 provider=provider, 

206 model=model or "", 

207 posture=posture, 

208 reason=REASON_OFF_NOT_EXPRESSIBLE, 

209 )
