Guardrail Architecture & Code Walkthrough

Executive breakdown of folder responsibilities, file invocation sequence, and delegation to Granite Guardian 4.1 8B (apps/text) and GLiNER 205M (apps/nlp).

⚖️

Key Concept for Your Walkthrough: Policy Conductor & Delegation Service

apps/guardrail owns the policies, boundaries, rate limiting, and fail-closed rules. It focuses on high-speed orchestration. When an LLM judge is required, it delegates to apps/text. When token classification (NER) or toxicity classification is required, it delegates to apps/nlp.

💡 Quick Presentation Takeaways (3 Bullet Points for Leadership)
🎯
1. Strict Separation of Concerns

Guardrail acts as the security router and policy enforcement layer. High-resource model inference is cleanly offloaded to dedicated pods (apps/text and apps/nlp).

🛡️
2. Fail-Closed Resilience

If an internal peer service (like LM Studio or NLP) drops or errors out, Guardrail rejects the untrusted prompt with HTTP 503 rather than leaking raw patient data.

⚡
3. Specialized Models for Speed

We use lightweight GLiNER2 (205M) for sub-30ms PII entity extraction and Granite Guardian 4.1 8B for authoritative clinical intent evaluation.
