### 1. Replay compatibility (6) — re-fixtured onto `core.*`

fan-out stage, one DEGRADED node settling beside SUCCEEDED siblings) are now authored out of

its two stubs — the same technique `_capture_core_replay_fixture.py` already used.

`interpreter_v1_history.json` and `interpreter_stream_v1_history.json` were recaptured. They are
genuinely different eras: 38 events / 0 emits / no marker vs 82 events / 7 emits / marker present.

**Deviation, deliberate:** the pre-stream era is now SYNTHESISED. The shipped interpreter emits a
run-completed event on EVERY run, so no capture of it can omit the `task-849-run-event-stream`
marker; `--no-stream` suppresses the mirror for the capture only (and must run the worker
unsandboxed, or the workflow sandbox re-imports the shipped method). Replay always runs against
the real method, so the backward guard still tests exactly what it tested. It is synthesised
because the genuine pre-stream recordings walked the retired `noop`/`passthrough` vocabulary.

`TestCoreVocabularyReplayCompatibility`'s backward guard was RE-STATED, not weakened: it used to
say "no history recorded before this ticket carries a `core.*` node", which is now false of every
fixture; `_CORE_PATCH` is consulted only for `core.humanReview` / `core.loop`, neither of which the
interpreter fixtures carry — which is the property the cheap-operand-first gate actually has.
